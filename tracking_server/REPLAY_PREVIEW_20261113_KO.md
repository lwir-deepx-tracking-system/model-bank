# 녹화 미리보기 작업 분리

## 확인한 병목

기존 교대 투입을 고정하고 같은 212장의 16비트 녹화를 시청자 있음 → 없음 → 없음 → 있음 순서로 재생했습니다. 회차마다 앞뒤 10장을 제외했습니다. 시청자 없음에서도 초당 한 번의 JPEG는 생성하므로, 이는 JPEG 함수 단독 시간이 아닌 화면 생성·송출 경로 전체의 진단입니다.

| 서버 측 시간 | 시청자 1명 | 시청자 없음 |
|---|---:|---:|
| 입력 수신 → 추적 결과, 평균 | 126.90ms | 47.63ms |
| 입력 수신 → 추적 결과, 중앙값 | 88.30ms | 45.44ms |
| 입력 수신 → 추적 결과, p95 | 254.62ms | 62.03ms |
| 추적 결과 출력 간격, 평균 | 39.47ms | 35.98ms |
| 추적 결과 출력 간격, p95 | 53.99ms | 52.20ms |

네 회차 모두 212장을 순서대로 처리했습니다. 코어별 투입은 106/106, 프레임 누락·순서 오류는 0, 오검출 0·미검출 60·ID 전환 3으로 일치했습니다. 입력은 30fps로 요청한 저장 영상이며, 실카메라나 브라우저까지의 전체 지연은 아닙니다. 시청자 없음을 운영 해결책으로 삼지 않습니다.

## 변경 범위

검출·추적·채점은 기존 순서로 처리합니다. 재생 화면의 픽셀과 박스, 표시 정보를 복사해 제한된 작업 대기열에 넣고 화면 그리기와 JPEG 압축을 분리합니다. 실시간 카메라의 기존 최신 화면 우선 방식은 유지합니다.

재생은 처리 중 한 장과 대기 한 장으로 제한하고, 대기열이 차면 생산자가 기다립니다. 정상 재생 중 화면 작업을 버려 숫자를 개선하지 않습니다. 영상 전환·탐색으로 무효가 된 작업은 새 화면에 게시하지 않습니다. 슬라이더 위치는 준비된 JPEG를 기준으로 표시하며 탐색 대상과 마지막 프레임은 시청자가 없어도 만듭니다.

옵션은 `LWIR_ASYNC_PREVIEW=1`과 `LWIR_ASYNC_REPLAY_PREVIEW=1`입니다. 미설정이면 기존 동기 재생을 유지합니다. 비교 시 재생 시작 요청에 `preview=sync` 또는 `preview=async`를 지정하고 `state.preview`로 실제 방식을 확인합니다. 진행 중인 회차의 방식은 바꾸지 않습니다.

## 검증 상태

PC 회귀 82개(기존 76개 + 신규 6개)를 통과했습니다. 느린 인코더에서 JPEG 바이트·표시 순서·대기열 상한·탐색 후 게시·종료·실패·시청자 없는 마지막 프레임을 검사했습니다. 독립 검토에서 발견한 옵션 조합의 이전 라이브 JPEG 덮어쓰기도 수정했습니다. 코드 `a2c70ee`를 장치에 적용하고 ARM64에서도 회귀 82개가 통과했습니다. 기존 v27 바이너리·제어값·검출 모델·추적 설정·8770 라벨 서버는 유지했습니다. 카메라가 연결되지 않은 현재 조건을 실카메라 성능으로 확대하지 않습니다.

기존 재생 프로그램은 탐색 요청마다 고유한 응답 번호를 돌려주지 않습니다. 같은 위치로 빠르게 반복 탐색하거나 반복 재생 경계에서 탐색하면 요청별 완료를 엄밀히 구별하지 못할 수 있습니다. 새 화면 위치는 실제 게시한 JPEG와 일치하지만 이를 개별 명령의 수신 확인으로 해석하지 않습니다. 이번 성능 비교는 탐색 없는 첫 회차입니다.

## 같은 서버에서 동기/비동기 비교 완료

동일 프로세스에서 **동기 → 비동기 → 비동기 → 동기** 순서로 비교했습니다. 모두 코어 0·1 교대, 시청자 1명, 동일 212장, 30fps 요청, 같은 검출·추적·외형 설정, 영상 파일 저장 꺼짐입니다. 각 회차 시작 전 31초 이상 JPEG가 나오지 않은 구간을 확보해 서버의 30초 지연 창에 이전 회차가 섞이지 않게 했습니다.

| 지표 | 동기 | 비동기 |
|---|---:|---:|
| 입력 수신 → 추적 결과, 평균 | 117.97ms | **43.62ms** |
| 입력 수신 → 추적 결과, 중앙값 | 112.31ms | **43.90ms** |
| 입력 수신 → 추적 결과, p95 | 240.53ms | **52.80ms** |
| 추적 결과 출력 간격, 평균 | 37.39ms | **35.36ms** |
| 추적 결과 출력 간격, p95 | 51.90ms | **50.79ms** |

추적 시간은 회차마다 앞뒤 10장을 제외한 각 192장(간격 191개)을 두 회차씩 합쳤습니다. 평균 입력→추적 지연은 63.0% 줄었지만 **평균·p95 출력 간격 모두 33.3ms를 충족하지 못했습니다.** 한 프레임의 대기는 크게 줄었고 지속 출력 속도의 개선은 상대적으로 작았습니다.

| 회차 | 방식 | JPEG 준비 지연 중앙값 | JPEG 준비 지연 p95 |
|---|---|---:|---:|
| 1 | 동기 | 135.8ms | 272.3ms |
| 2 | 비동기 | 62.1ms | 73.1ms |
| 3 | 비동기 | 63.0ms | 73.1ms |
| 4 | 동기 | 103.4ms | 256.6ms |

JPEG 시간은 각 회차의 원본 212장 전체 백분위입니다. 원시 표본이 없는 백분위를 평균 내거나 추적 시간 표와 같은 표본인 것처럼 합치지 않았습니다. 둘 다 서버 수신 이후의 시간이며 센서·네트워크·브라우저 표시 시간은 포함하지 않습니다.

네 회차 모두 처리·채점·JPEG 게시 212/212장, 코어별 106/106장, 입력·서버 누락·순서 오류·미리보기 폐기·압축 오류 0건입니다. 최종 표시 위치는 0부터 세는 211이었습니다. 점수는 모두 오검출 0, 미검출 60, ID 전환 3, IDF1 69.96%, HOTA 63.6171%, 사람 AP50 99.6488%, AP50:95 78.0080%로 일치했습니다. 이 녹화의 기존 무시 영역·검수 규칙을 적용한 결과이며 전체 프로젝트 정확도나 새 일반화 결과가 아닙니다.

별도 기능 검증에서는 시청자가 없어도 마지막 프레임을 게시했습니다. 51번째와 121번째 프레임으로 되감아 일시정지했을 때 위치·이미지가 고정되고, 다시 재생해 끝에 도달해도 첫 회차 채점은 늘어나지 않았습니다. 실제 JPEG는 기존과 같은 960×720입니다. 원본 입력 640×480을 1.5배 표시하는 기존 설정을 이번 비교에서는 유지했습니다.

**채택:** 장치의 재생 비동기 옵션을 켠 채로 유지하고 코드·기록을 main에 반영했습니다. 시험용 재생·시청 연결·측정은 종료했으며 교대 투입은 켜져 있습니다. 다음 후보는 모델 입력을 유지한 채 불필요한 1.5배 표시 확대를 없애는 방법입니다. 아직 이 후보는 적용하거나 속도를 측정하지 않았습니다.
