# 예측 제어 실제 저속 비교 — 2026-11-12

## 결론

실제 짐벌로 세 쌍을 비교했다. **중심 유지와 화면 이동량을 모두 개선한 설정은 아직 없다.** 150ms나 60ms를 새 운영 최적값으로 채택하지 않았다. 운영 서버를 원래 실행 경로로 복구했고 예측은 꺼진 상태를 확인했다. 새 Python·v27 예측 경로는 별도 시험에서 썼으며 운영 코드에는 아직 적용하지 않았다.

카메라의 이동까지 포함한 화면 기준 60ms는 장면 기준 60ms보다 가로 오차 p95와 화면 속도 p95가 작았다. 그러나 총 이동량은 늘었다. 이 부분 개선을 모든 조건의 성공으로 표현하지 않는다.

## 무엇을 실제로 재었나

- 현장 사용자가 짐벌 옆에서 즉시 정지할 수 있음을 확인한 뒤 실행했다.
- 실제 카메라·짐벌, 새 LEAD/epoch 경로, 가상 표적 가로 60px 왕복. 검출기나 실제 사람이 걸어가는 시험은 아니다.
- PD30/0/6, 불감대 0.06, 조준 높이 0.08, 속도 명령 상한 10. 실제 최대 명령 5. 운영 상한 100의 검증이 아니다.
- 박스 전달에 40ms 지연을 주었다. 시각은 카메라 수신 시각이며 센서 노출 시각이 아니다.
- 관측·예측·제어기 적용값·실제 직렬 명령을 연결해 기록했다. 원본 16비트 영상 1782장과 로그는 비공개 실험 자료로 보존했다.
- 템플릿 정합과 별도 광류 정합을 대조했다. 실제 관절 각도 측정은 아니다.
- 첫 정합/프레임/정지 오류에서 전체 종료한다. 정지 쓰기 실패는 후속 성공으로 지워지지 않는다. 종료 뒤 동결 영상과 움직임도 확인한다.

## 3. 화면 기준 60ms → 장면 기준 60ms

장면 기준은 GMC로 카메라 움직임을 빼서 얻은 대상 속도를 사용한다. 화면 기준은 관측이 화면에서 실제로 움직이는 속도를 사용한다. 예컨대 대상이 장면에서 오른쪽으로 움직여도 카메라가 더 빠르게 오른쪽으로 돌면 영상에서는 왼쪽으로 움직인다. 이때 두 예측의 부호가 다를 수 있다.

| 항목 | 장면 기준 | 화면 기준 |
|---|---:|---:|
| 가로 오차 중앙값(px) |13.89|12.47|
| 가로 오차 p95(px) |29.24|27.79|
| 화면 이동량(px) |119.79|126.52|
| 화면 속도 p95(px/s) |137.10|96.10|
| 명령 변경 횟수 |18|16|
| 방향 반전 / 이동 시작 |1 / 2|1 / 2|

각 176프레임. 화면 기준은 오차 p95 약 5%, 속도 p95 약 30% 감소, 이동량 약 5.6% 증가다. 각 쌍은 한 번씩이며 시작 구도 차이와 동역학 변동이 있으므로 앞 표의 숫자를 합쳐 순위를 매기지 않는다. 화면 기준은 기존 D와 비슷한 변화율을 P에도 반영하므로 미분 효과 중복과 노이즈를 추가 검증해야 한다.

모든 주행 구간에서 가상 대상 놓침 0, 방향 반전 1회였다. 이는 실제 사람 검출 누락이나 가림 복원 성공률이 아니다. 세로 이동·근거리·실제 사람·고속 조건은 미검증이다.

## 갑자기 사라질 때

**급이동과 관측 소실은 다른 조건이다.** 사용자는 갑자기 움직이는 사람도 카메라가 따라가야 한다고 명확히 했다. 같은 ID의 유효한 관측이 들어오면 현재 제어기는 큰 위치 변화만으로 이를 버리지 않고 새 위치로 추종한다. 아래 정지 시험은 빈 관측·다른 ID·끊긴 입력에 대한 시험이며, 빠른 이동에 대한 정지 정책을 권하는 뜻이 아니다. 현재는 한 프레임의 검출 누락도 STOP을 유발할 수 있어 급이동 중 끊김의 원인이 될 수 있다. 정상 영상의 짧은 검출 누락과 영상 자체 중단을 구분하는 보완이 필요하며, 이 보완을 운영에 적용했다고 주장하지 않는다.

새 브리지의 가상 직렬 포트에서 예측이 적용된 이동 상태를 만든 뒤 시험했다. 물리적 모터는 연결하지 않았으며 아래 수치는 **프로토콜 입력 이후 정지 명령 출력까지**다.

| 상황 | 결과 | 시간 |
|---|---|---:|
| 선택 ID가 사라짐(F/G) | STOP, 다른 ID로 넘어가지 않음 |약 20–22ms|
| 근처에 다른 ID만 남음(F/G) | STOP, 선택 ID 유지 후 대기 |약 20–22ms|
| 영상 입력만 중단, heartbeat 유지 | 입력 유효기간에 맞춰 STOP |시험 시작 후 약 223ms|
| 미래 시각 입력 | STOP |약 21ms|
| 새 프레임 번호·반복 캡처 시각 | STOP |약 46ms|

입력 유효기간 기본값은 캡처 시각 기준 250ms다. 영상 입력 중단 시험을 시작했을 때 마지막 프레임이 이미 일부 경과했으므로 223ms와 250ms를 같은 기준으로 읽지 않는다. 재등장한 같은 ID가 중앙에 있으면 옛 epoch 예측으로 움직이지 않았고, 다시 바깥에 나타나면 관측에 따른 명령만 나갔다.

**미확인:** 물리적 감속·완전 정지 시간, 한 프레임의 짧은 소실이 최신값 슬롯에서 덮이는 경우, 추적기가 서로 다른 사람에 같은 ID를 붙인 경우, 상위 경로가 동결 영상에 새 시각을 붙이는 경우. 숫자 ID를 유지한다는 사실만으로 같은 물리적 사람임을 보장하지 않는다.

## 급이동·급반전 소프트웨어 확인

사용자의 급이동 요구를 반영해 실제 v27 제어기와 기록용 가상 장치로 6개 회귀 검사를 추가했다. 같은 ID의 가로 위치를 320 → 512 → 128px로 바꾸고 PD30/0/6, 속도 상한 10을 사용했다.

| 조건 | 오른쪽 첫 명령(ms) | 왼쪽 반전 명령(ms) |
|---|---:|---:|
| 예측 끔 |0.04|47.87|
| 반대 방향의 현재 예측 |32.04|47.75|
| 이전 선택의 예측 |30.48|47.98|

프레임 전달부터 가상 장치 호출까지의 단일 실행값이다. 실제 짐벌의 따라잡는 시간이나 조건 간 속도 우위가 아니다. 급이동은 관측으로 따라가며 옛 예측은 무시했다. 한편 60ms 동안 빈 관측 한 장을 넣자 30.43ms 뒤 STOP, 같은 ID 재등장 뒤 31.48ms에 재개했다. **한 프레임 검출 누락의 정지·재시작 문제를 해결한 결과가 아니라 재현한 결과**다. 수동 정지·연결 끊김 뒤에는 새 관측과 옛 예측으로 재시작하지 않았다.

다음 보완은 정상 라이브 영상의 짧은 검출 누락과 영상 자체 중단을 구분하는 것이다. 현재 F/G의 빈 관측에는 동결·재생 차단도 섞일 수 있으므로, 입력 유효성 표시 없이 무조건 명령을 유지하도록 바꾸지 않는다. 급이동은 따라잡기를 우선하고, 잘못된 관측이나 장시간 소실에 대한 정지는 별도로 유지한다.

## 재현 도구

- `predictive_ab_hil.py`: 기본은 가상 카메라/PTY. 실제 실행은 `--execute --attended`가 필요하다. 운영 프로세스가 있거나 직렬 장치가 사용 중이면 거부한다. 자동 재시작·자동 복귀 동작은 없다.
- `--lead-ms 150` 또는 `--lead-ms 60 --candidate-first`: 공통 조건의 OFF/ON 비교.
- `--reference-comparison`: 화면 60ms → 장면 60ms. `--lead-ms` 값은 이 모드에서 사용하지 않는다.
- `../test_v27_disappearance.py`: 장치를 움직이지 않는 소실·입력 중단 검사 7종.
- `../test_v27_fast_motion.cpp`: 실제 제어기와 가상 장치로 급이동·반전·한 프레임 누락·수동 정지·연결 끊김을 검사한다.
- `analyze_predictive_ab.py <완료된 결과 폴더>`: 같은 프레임 시각으로 중심 오차·이동량·실제 명령을 재집계한다. 실패하거나 정지 확인이 끝나지 않은 결과는 순위를 계산하지 않는다.
- `LWIR_CONTROL_TRACE=1`: 제어기 stderr JSON 계측. 기본은 꺼짐. 쓰기 지연이 생길 수 있으므로 짧은 계측에만 사용한다.

화면 기준은 `estimate(..., space="image")`로 명시 선택하는 실험 옵션이다. 운영 기본 `scene`과 기존 관측 박스는 변경하지 않았다. Python 29개, C++ 3종, trace 파서, ARM64 실제 브리지 기반 가상 비교·소실 검사를 확인했다.
