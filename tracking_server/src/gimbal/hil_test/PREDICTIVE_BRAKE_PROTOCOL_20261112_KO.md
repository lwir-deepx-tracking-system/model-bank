# 가로 예측 제동 A/B 시험

가상 표적을 중심 근처에 유지하면서 불필요한 화면 왕복이 줄어드는지 본다. 실제 브리지에서 A는 `--predictive-brake 0`, B는 `--predictive-brake 1`로 실행한다. 두 조건 모두 PD 30/0/6, SPD 상한 7, LEAD·catch-up 끔이다. 기존 운영과 달리 두 조건에서 관측 유예를 끄고 입력 손실에 즉시 시험을 중단한다. 표적 상하 조준점은 중앙으로 고정하며, 직렬 감독기는 Y 명령과 SPD 7 초과를 물리 직렬로 보내기 전에 차단한다.

## 규약

- A → B → B → A 네 블록을 같은 실행에서 측정한다. 각 블록의 정지 상태에서 공통 기준 장면 대비 상하 35px, 가로 65px 이내인지 두 정합법으로 확인하고 그 블록의 영상 원점을 기록한다. 장치의 물리적 위치를 자동 재설정하지 않는다.
- 단일 가상 ID에 같은 4.6초 자극을 적용한다. 가로 0px 0.5초, 0→60px 0.3초, 60px 1.3초, 60→0px 0.6초, 0px 1.3초, 0/4/0/−4px 반복 0.6초 순이다. 표적 위치는 해당 관측의 타임스탬프 시점까지의 프로필과 현재 등록 변위만 사용한다.
- 실제 카메라 SDK 수신에서 관측 발행까지 공통 40ms를 부과한다. 65ms를 넘기면 중단한다. SDK 수신, 완전한 파이프 도착, 프레임 수거, 등록 시작·완료와 등록 스레드 CPU 사용 시간, 장면 한도 확인 잠금, heartbeat 전송, 관측 발행과 직렬 쓰기 시각을 보존한다. 카메라 노출 시각과 모터 수신 시각은 측정하지 않는다.
- 전체 RAW16이 같은 프레임을 보존하되 새 관측이나 감시 타이머 갱신에 사용하지 않는다. 180ms 안의 다음 고유 등록을 요구한다. 고정 템플릿과 LK가 실패하거나 서로 어긋나면 중단한다. 공통 시야는 가로 130px, 상하 65px이며, 95px부터 바깥 방향 가로 명령을 차단한다. 표적 가로 오차 한도는 110px다.
- 블록이 끝나거나 오류가 나면 브리지와 독립적으로 직접 STOP을 쓰고 후속 움직임을 차단한다. 각 블록과 최종 종료에 1.2초 이상 새 등록을 모으고 후기 350ms 이상, 최소 6장에 두 방법의 좌표 변동 1.5px 이하를 요구한다. 최대 제어시간 45초다. 손실·시각·정합·프로토콜·직렬·시야·정지 검증 실패는 실행 실패로 보존하고 이후 블록을 실행하지 않는다.

## 판정

블록별 중심 가로 절대 오차 MAE·p95, ±19.2px 안 비율, 정착 마지막 0.3초 절대 오차 가중 중앙값, 전체 가로 영상 이동, 정지 구간별 총 변동과 순이동, 초과 이동량, 방향 반전과 STOP 후 재출발, 실제 예측 STOP 수를 보고한다. 오차의 평균·p95·중앙값 및 범위 안 비율은 각 고유 관측의 값을 다음 관측 직전까지 유지하여 공통 프로필 시간으로 가중한다. 초과 이동량은 총 변동에서 순이동의 절댓값을 뺀다. 단순 이동량은 왕복이나 떨림과 별도로 본다. 지표의 고정 구간은 static·dwell·settle이며 jitter는 별도로 보고한다. 실제 예측 STOP은 발행한 관측과 브리지 계측, 이후 직렬 전달 기록을 대조한다.

후보가 한 번 이상 발동하고 두 비교 쌍에서 모두 중심 허용범위 비율이 유지되며, 정착 오차가 대조보다 1px 넘게 늘지 않고, 110px 밖 관측이나 STOP 후 재출발이 늘지 않으며, 정지 구간의 초과 이동량이 줄면 잠정 개선으로 기록한다. 두 B가 모두 발동하지 않으면 `candidate_no_op`로 기록한다. 실패나 불완전한 실행으로 후보를 선정하거나 같은 실행 중 기준값을 바꾸지 않는다. 이 자극의 표적은 고정 배경으로 계산한 가상 좌표이므로 실제 사람, 세로, 고속 성능은 별도로 검증해야 한다.

## 실행

리눅스에서 장치 없는 실행이 기본이다. 새 결과 폴더와 별도로 빌드한 실제 브리지를 지정한다. 합성 카메라는 SPD 1에서 112px/s, SPD 7에서 212px/s, 그 사이는 선형 보간으로 설정한다. 합성 지연은 105ms, 속도 응답의 시정수는 27ms다. 이 값은 관측을 참고해 만든 하나의 소프트웨어 장면이며, 모터 지연 추정이나 실기 결과로 사용하지 않는다.

```bash
python3 predictive_brake_ab_hil.py --bridge /path/to/isolated_bridge --out /private/new_dry_output
```

물리 실행에는 위 인수와 `--execute --attended --camera /path/to/current_stamped_cam_pipe`가 함께 필요하다. 현장 정지 담당자가 대기하고 카메라 영상과 가로 회전 공간을 확인한 상태에서 실행한다. 운용 중인 카메라·추적 서버·직렬 점유가 있으면 시작하지 않는다. 결과는 저장소 밖의 새 전용 폴더에 저장한다. 가상 시험의 실제 브리지 동작과 물리 카메라 동작은 별도 증거다.

같은 CPU 배치를 모든 A/B 블록에 적용하려면 선택 인수 `--profile-cpus 4,5,6,7`을 사용할 수 있다. 카메라와 브리지, 직렬 감시 스레드를 생성한 뒤 프로필을 처리하는 호출 스레드에만 적용하고 블록마다 원래 CPU 집합을 복원한다. 실제 적용값과 복원값을 블록에 기록한다. 40/65ms 및 STOP 규약은 그대로 적용한다.
