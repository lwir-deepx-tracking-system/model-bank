# 가로 고정 속도 → 단독 정지 기록

가로로 정해진 속도 명령을 한 번 보낸 뒤, 다른 이동 명령 없이 STOP을 보낸다. 열화상 고정 배경이 움직이기 시작하고 다시 평탄해지는 구간을 두 영상 정합법으로 기록한다. 자동 추종, 사람 검출, NPU, 예측 제어 및 상시 운영값은 이 시험에 사용하지 않는다.

| 순서 | 가로 명령 부호 | SPD | 명목 유지 |
|---|---:|---:|---:|
| 1 | +1 | 1 | 250 ms |
| 2 | −1 | 1 | 250 ms |
| 3 | −1 | 7 | 350 ms |
| 4 | +1 | 7 | 350 ms |

카메라 첫 영상 이후 약 5초 기다린다. 각 펄스 직전 최소 600ms 정지 화면과 직렬 STOP 이후 최소 1.2초를 저장한다. 각 펄스당 이동 명령과 명목 STOP은 각각 한 번이며, 시작/종료/실패의 안전 STOP은 따로 표시한다. 첫 비교의 각 조건은 한 표본이고 SPD별 유지 시간이 다르다. SPD 7의 350ms는 기존 기록의 130–185ms 영상 반응 뒤에도 STOP 이전 프레임을 더 남기기 위해 고정했다. 초기 응답 관측에 쓰며 정상속도 도달이나 반복 재현성을 전제하지 않는다. 복귀를 별도 구동하지 않는다. 세 번째 시험 후에도 다음 시험 시작 변위 한계(65px, 35px)를 넘으면 네 번째 명령을 보내지 않는다. 반대 부호가 원위치 복귀를 보장하지 않으며 마지막 위치는 운용자가 화면으로 확인한다.

양쪽으로 움직일 여유가 있는 장면에서 진행한다. 프레임 전체를 저장하되 정합은 상단 고정 구조물만 사용한다. 기본 영역은 원본 640×480에서 x=16..623, y=0..179다. 사람과 움직이는 물체는 이 영역을 가리지 않아야 한다. 다른 장면에서 영역을 넓힐 때만 실행 전에 프리뷰로 고정 배경임을 확인하고 `--background-bottom`을 지정한다. 첫 정지 구간부터 대비, 고정 템플릿 일치와 유일성, 전후방 LK 점 수·일관성, 두 방법 간 합의를 검사한다. 특징이 부족하면 이동 명령 없이 중단한다. 현장에 사람이 있고 물리적으로 즉시 정지할 수 있어야 한다. 운영 추종 서버·기존 카메라 프로그램을 정상 종료하고 자동 재시작이 멈춘 상태에서 실행한다. 이 도구가 다른 프로세스를 종료하거나 다시 시작하지 않는다. 안정된 직렬 장치가 하나이고 사용 중이지 않은지 확인하며 열 때와 연 뒤 독점성을 확인한다. 카메라 프로그램의 자체 잠금도 유지한다.

등록·카메라 시각·RAW16 연속성·직렬 오류나 시야 한계에 실패하면 다음 이동을 보내지 않고 STOP을 보낸다. 절대 변위 한계는 시작 영상 기준 가로 130px·세로 65px이며, 다음 펄스 시작에는 65px·35px의 여유 조건이 추가로 적용된다. 등록에 사용하는 실기 프레임은 SDK 수신에서 파이프 도착까지와 SDK 수신에서 정합 완료까지가 각각 180ms 이내여야 한다. 카메라 처리와 별도인 감시 스레드가 명목 STOP과 전체 허용시간을 관리하며, 이동 중에는 마지막으로 정합을 통과한 프레임의 SDK 수신 시각부터 나이를 계산한다. 각 STOP에 앞서 줄바꿈을 전송해 앞선 직렬 쓰기가 잘려도 STOP이 별도 줄에 놓이게 한다. 장치 제어는 최대 30초로 닫으며, 그 뒤 원본 저장 시간이 추가된다. 현장 운영자는 시스템 정지·전원 상실·직렬 분리에 대비해 물리 정지 수단을 유지한다.

기록 형식 2에서는 직전 프레임과 전체 RAW16이 완전히 같으면 해당 프레임과 시각을 보존하고 정합 및 감시 갱신에서 제외한다. 고유 프레임을 기다리는 총 한도와 마지막 고유 정합의 SDK 수신 이후 허용 나이는 각각 180ms다. 같은 프레임이 계속 와도 이 한도는 연장되지 않는다. 전체 프레임은 달라졌는데 배경 영역만 같은 경우에는 기존 배경 동결 검사로 중단한다.

기본값은 장치 없이 합성 카메라와 가상 직렬 쓰기를 사용한다.

~~~bash
python3 -B /path/to/repo/tracking_server/src/gimbal/hil_test/test_fixed_pulse_hil.py -v
python3 -B /path/to/repo/tracking_server/src/gimbal/hil_test/fixed_pulse_hil.py \
  --repo /path/to/repo --out /path/to/new/private/dry-output
~~~

현장 조건을 확인한 뒤 Linux에서 아래처럼 실행한다. 기본 카메라 실행 파일이 다른 곳에 있을 때만 현재 버전의 카메라 프로그램을 **직접** 지정한다. 프레임 머리표가 없는 옛 바이너리는 영상 검증 단계에서 중단하며, 형식을 낮춰 재시도하지 않는다. 출력은 새 경로이며 저장소 밖에 둔다. 종료 코드 3은 중단 또는 검증 실패이며 부분 결과를 보존한다. 결과를 확인하기 전 자동으로 반복하지 않는다.

~~~bash
python3 -B /path/to/repo/tracking_server/src/gimbal/hil_test/fixed_pulse_hil.py \
  --repo /path/to/repo --camera /path/to/current/cam_pipe \
  --out /path/to/new/private/physical-output --execute --attended
~~~

- `raw16/`: 프레임 번호와 파이프 수신 완료 단조 시각을 이름에 넣은 640×480·16비트 무손실 PNG.
- `frames.jsonl`: 카메라 SDK의 `RecvImage` 직후 호스트 시각, 전체 프레임이 파이프를 통과한 시각, 고정 템플릿 정합과 프레임 간 LK의 각각의 이동량, 정합 상태. 전체 RAW16 중복은 `duplicate_full_raw16: true`와 `valid: false`로 표시한다. 처리 전에 종료된 프레임의 중복 여부와 실제 센서 노출 시각은 `null`이다. 합성에서는 SDK 수신도 `null`이다.
- `serial.jsonl`: 직렬 쓰기 직전·직후 호스트 시각, 명목 STOP 예정 시각, 명령·결과 및 수신 바이트. 쓰기 완료는 장치 수신이나 구동 적용 확인으로 해석하지 않는다.
- `result.json`: 각 STOP 뒤 실제 확보한 시간, 후기 평탄부의 정합별 흔들림과 최종 화면 확인. 기준 정지 구간에서 1px 문턱을 넘은 프레임이 없고, 두 방법이 같은 방향에서 1px 이상인 연속 고유 프레임 두 장을 검출하며, 두 시작 구간이 겹칠 때 호스트 도착 기준 응답을 보고한다. 나머지는 미확정으로 남긴다. STOP 전 마지막 고유 도착·STOP 후 첫 고유 도착에서 후기 평탄부까지의 영상 변위를 각각 제공한다. 두 값에는 프레임 도착 시각과 실제 움직임 시각의 차이가 포함된다.
- `camera.log`: 카메라의 자체 동작 기록.

이 자료로는 장면의 영상 변위와 호스트 기준 응답 구간을 비교한다. 센서 노출, 직렬 수신·모터 적용 시점, 실제 관절 각도와 속도, SPD 100, 세로·대각선 응답은 측정하지 않는다. 원본·장치 로그·실행 경로는 공개 저장소에 올리지 않는다.
