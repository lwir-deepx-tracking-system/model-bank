# 일정 속도 → 정지 응답: 실제 카메라 결과

**세 번째 장치 시도에서 네 조건의 고정 속도→단독 STOP 기록을 완료했습니다.** 첫 시도의 배경 부족, 두 번째 시도의 중복 프레임 중단을 보존하고 원인을 고친 뒤 수행했습니다. 운영 서버는 정상 복구했고 예측 보정은 꺼 둡니다. 이 네 표본만으로 전체 속도 범위의 제어값을 바꾸지 않습니다.

## 최신 완료 결과

사용자가 사람이 없는 고정 가구 장면으로 방향을 바꾸고 조정을 마쳤음을 확인했습니다. 사전 규약에서 허용한 원본 상단 360행의 고정 배경을 사용했습니다. 이동·시야·영상 나이 한도는 유지했습니다.

| 가로 명령 | 명령→첫 영상 반응 구간 | STOP 후 첫 수신 영상→정착부 이동 |
|---|---|---|
| SPD 1, +방향, 250ms | 167.0–218.3ms | 9.31–10.08px |
| SPD 1, −방향, 250ms | 122.5–176.6ms | 0.12px |
| SPD 7, −방향, 350ms | 167.4–218.1ms | 6.99–7.33px |
| SPD 7, +방향, 350ms | 131.1–180.3ms | 7.07–7.63px |

방향은 명령의 부호입니다. 첫 반응은 기준에서 같은 방향으로 1px 이상 이동한 연속 두 영상으로 판단하며, 앞뒤 프레임 사이 구간으로 표시했습니다. 변위 범위는 고정 템플릿 정합과 독립 LK의 두 측정값입니다. **센서 노출·모터 명령 수신 시각을 모르므로, 위 시간을 모터 자체 지연으로, 마지막 열을 물리적인 STOP 이후만의 제동 거리로 해석하지 않습니다.**

STOP 직전 마지막 수신 영상에서 정착부까지는 위 순서대로 16.17–16.46px, 5.51–5.80px, 17.93–18.36px, 15.22–15.54px였습니다. 첫 STOP 후 영상과의 차이가 큰 것은 프레임 사이의 미관측 움직임과 수신 시각 불확실성을 함께 보여 줍니다.

- 실제 명령 유지 시간: 250.1 / 254.4 / 354.1 / 353.7ms.
- 각 명목 STOP 이후 기록: 1.217 / 1.254 / 1.222 / 1.218초. 그 사이 다른 이동 명령 없음.
- 네 조건의 후기 정착부 흔들림: 가로·세로, 두 정합법 모두 0.074px 이내. 마지막 STOP 뒤 독립 화면 안정 검사 통과.
- RAW16 329/329장 보존, 중복 34장도 삭제하지 않고 표시. 중복은 새 관측이나 감시 타이머 갱신에 사용하지 않음.
- 직렬 쓰기·감시 타이머 오류 없음. 8090 정상 복구, 자동 추종·LEAD 꺼짐, 기존 PD·바이너리·8770 유지.
- 완료 원본 묶음 SHA256: `6ed9b50b0fa9871fff0488d2cacbfbf5140cdfbecb0cac435843034c9b666116`.

이번 결과는 정지 명령을 보내도 다음 수신 영상에서 이동이 계속 보일 수 있음을 확인합니다. 반응을 즉시라고 가정하거나 하나의 고정 시간만 모든 속도·방향에 적용하는 근거는 부족합니다. 다음 설계에는 관측 지연을 포함한 영상 응답 구간과 속도·방향에 따른 불확실성을 사용해야 합니다. 실제 사람 급이동·세로·SPD 100에서의 검증과 반복 측정은 남아 있습니다.

## 목적과 조건

속도 명령이 계속 달라진 이전 기록으로는 각 명령의 반응과 정지 뒤 이동을 분리하기 어려웠습니다. 그래서 가상 표적 시험의 별도 구간으로, 같은 속도 명령을 유지한 뒤 다른 이동 명령 없이 STOP을 보내도록 만들었습니다. 실제 사람 추종이나 검출 성능 비교는 아닙니다.

[고정 규약](FIXED_PULSE_PROTOCOL_20261112_KO.md)은 가로 SPD 1·7을 양방향에서 한 번씩 측정합니다. 각 STOP 뒤 최소 1.2초를 확보하고 두 정합법으로 영상 이동을 확인합니다. 첫 시도는 사람이 움직일 수 있어 원본 640×480의 상단 180행 중 고정 배경만 사용했습니다. 사용자 장면 조정 이후의 두 번째·세 번째 시도는 위의 상단 360행 조건입니다. 이동 전에 배경 품질을 검사하며 실행 후 기준을 완화하지 않습니다.

## 보존한 첫 시도: 배경 품질 부족

| 항목 | 결과 |
|---|---|
| 실제 이동 명령 | **0회** |
| STOP 직렬 쓰기 | 6회, 전부 완전한 쓰기로 반환 |
| 원본 보존 | RAW16 115/115장 |
| 첫 중단 이유 | 고정 배경의 특징점 부족 |
| 종료 후 영상 정지 판정 | 같은 특징점 부족으로 확인 불가 |
| 서버 복구 | 카메라·브리지 정상, 자동 추종·LEAD 꺼짐 |
| 8770 및 기존 제어값 | 변경 없음 |

STOP 쓰기 성공은 호스트에서 데이터를 썼다는 뜻이며 모터의 수신·물리 정지 확인과 다릅니다. 이동 명령을 보내지 않은 이번 시도를 ‘물리 제동 검증 통과’로 표시하지 않습니다.

저장 원본을 다시 검사했습니다.

- 상단 특징점은 매 장 5–13개였고, 필요한 16개를 충족한 장은 115장 중 0장이었습니다.
- 인접 114쌍에서 기존 정합 검사를 그대로 적용하면 78쌍은 특징점 부족, 36쌍은 직전 영상과 동일해서 통과하지 못했습니다. 같은 36쌍은 상단뿐 아니라 전체 RAW16도 바이트 단위로 같았습니다.
- 중복 없이 이어진 57장·2.64초 구간도 있었습니다. 따라서 카메라 전체가 동결됐다고 단정하지 않습니다. 그 구간에서도 특징점은 부족했습니다.
- SDK 수신에서 파이프 수신 완료까지는 중앙값 3.592ms, p95 5.844ms, 최대 8.616ms였습니다. 이것은 센서 지연이나 전체 서버 지연이 아니며, 이번 중복의 원인이 파이프에 오래 쌓인 영상이라는 근거도 아닙니다.

원본 묶음 SHA256: `88c50297fe6c72ec5ad37f13b8cb457d3ae697240c2debf34b74060e9fbf01dc`. 원본 영상·장치 설정은 비공개 보존하며 이 저장소에 포함하지 않습니다.

## 도구 검증

최종 도구는 PC와 ARM64에서 각각 15개 검사를 통과했습니다. 장치 없는 가상 실행에서도 네 펄스와 각 단독 STOP, RAW16 보존 및 최종 화면 안정 검사를 완료했습니다. 실제 완료 증거는 위의 별도 세 번째 시도입니다.

독립 검토에서 발견한 두 문제는 실기 전에 수정했습니다. 밀린 SDK 영상을 새 파이프 도착으로 오인하지 않도록 원래 SDK 시각으로 신선도를 확인하고, 짧게 잘린 직렬 쓰기 뒤에도 STOP을 독립된 줄로 전송합니다. 최초 반응은 정지 영상의 변동이 작고 두 정합법의 방향·시간 구간이 맞을 때만 보고합니다.

## 보존한 두 번째 시도와 중복 처리 수정

장면을 바꾼 뒤 첫 펄스는 253.8ms에 명목 STOP으로 전환했습니다. 약 606ms 후 전체 RAW16이 직전 영상과 같아 즉시 중단한 기록입니다. 원본 171장과 마지막 화면 안정 확인을 보존하며, 이 시도를 1.2초 단독 STOP 완료로 세지 않습니다. 원본 묶음 SHA256: `97a0a6b077396a22ee2d15e407371bfe87cd4d6aa56900a5aba694db82db1aa4`.

저장 원본에서 다음 고유 영상은 직전 고유 관측 약 54ms 뒤 도착했습니다. 등록 구간의 고유 영상 최대 간격도 약 78ms였고 중복을 제외한 기존 정합 검사는 통과했습니다. 그래서 완전히 같은 전체 RAW16은 보존·표시하되 새 관측으로 세지 않도록 수정했습니다. 첫 중복 즉시 중단에서 **마지막 고유 관측 후 최대 180ms 안에 다음 고유 관측을 요구하는 방식**으로 바뀌었습니다. 중복 도착으로 이 한도나 감시 타이머를 연장하지 않습니다. 배경만 같고 전체 영상은 달라진 경우의 기존 정합 검사도 유지합니다.

독립 재검토와 15개 검사를 통과한 뒤에만 세 번째 시도를 수행했습니다. 같은 자료·조건에서 이유 없이 반복하지 않았으며, 실패 원본과 이전 도구 버전을 보존했습니다.

예측 기준점 수정 `52a0995`는 운영 장치에 이미 적용했고 관련 Python 검사 42개도 장치에서 통과했습니다. 이번에 확인한 응답을 반영한 새 운영 제어값은 아직 채택하지 않았습니다.
