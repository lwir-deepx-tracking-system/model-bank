# 한 프레임 관측 누락 보완: 적용과 검사

목표는 급하게 움직이는 사람의 정상 관측을 계속 따라가면서, 선택한 ID의 추적 행이 한 프레임 빠졌다는 이유만으로 불필요한 정지·재출발을 만들지 않는 것입니다. 정상 라이브 영상과 동결·재생·카메라 초기화를 구분했습니다. 검출기나 학습 가중치는 바꾸지 않았습니다.

## 적용

Python과 새 v27을 함께 8090에 적용했습니다. `--observation-grace-ms 100`을 켰으며 기존 PD 값과 속도 상한은 유지했습니다. 예측 `LEAD`는 꺼져 있습니다. 유예 중 마지막 명령만 유지하고, 같은 ID의 다음 관측은 즉시 반영합니다. 연속 누락·무효 입력·불명확한 프레임 순서는 정지합니다. 실제 유예는 100ms와 직전 관측 간격의 1.5배 중 작은 값이며, 기존 입력 만료 기한도 넘지 않습니다.

별도 설정은 [v27 변경 설명](../V27_CHANGES.md#11-12-정상-영상의-한-프레임-관측-누락)에 있습니다. 이는 장면·사람·속도 전 범위의 튜닝 완료가 아닙니다.

## 실제로 확인한 것

- PC Python 37개, 새 C++ 실행기 검사 26개와 기존 검사 40개 통과.
- Orange Pi에서 실제 ARM64 브리지를 빌드하고 기존 가상 직렬 검사 3종과 새 F/G 관측 검사 통과. 모터를 열지 않은 검사입니다.
- 합성 카메라와 실제 브리지를 연결한 모의 비교에서 정지·복귀·급반전 검사를 통과했습니다.
- 실제 카메라와 짐벌에서는 가상의 선택 ID를 사용했습니다. PD 30/0/6, 속도 상한 10으로 제한했고, 실제 출력 최대는 6이었습니다. 사람이 직접 움직이는 시험은 아닙니다.

실제 단독 조건 결과는 다음과 같습니다. **시작 화면과 누락 시간이 달라 공정한 성능 우위 비교로 쓰면 안 됩니다.** 각 행은 직렬 명령을 기록한 기능 확인이며 물리적인 모터 반응 완료 시간이 아닙니다.

| 관측 | 기존 유예 0 | 수정 유예 100 상한 |
|---|---:|---:|
| 빈 추적 행 발행→같은 ID 재발행 | 53.7ms | 16.6ms |
| 이 구간의 정지 명령 | 1회 | 0회 |
| 재발행→첫 같은 방향 명령 | 10.8ms | 0.65ms |
| 급반전 발행→첫 반대 방향 명령 | 35.9ms | 43.5ms |
| 마지막 정지 후 영상 안정 | 확인 | 확인 |

수정 조건은 빈 행 전송 2.3ms 뒤 `lost=1, moving=1, id=7`, 복귀 뒤 `lost=0, moving=1, id=7`을 보고했습니다. 즉 유예에 실제 진입한 뒤 같은 ID로 복귀한 증거가 있습니다. 두 번째 누락·만료·영상 이상 정지는 PC와 ARM64 가상 직렬 검사에서 확인했습니다. 이것들을 모두 실제 모터로 시험했다는 뜻은 아닙니다.

## 중단·실패를 보존한 내용

1. 첫 실기 기준 조건에서 시험기가 100ms 안에 상태 보고를 받지 못해 중단했습니다. 실제 같은 방향 명령은 56.6ms에 재개됐지만, 상태 보고는 101.5ms에 왔습니다. 브리지의 50ms 상태 조회 주기를 반영해 **상태 확인만** 175ms로 분리했습니다. 복귀 입력 100ms와 제어기 유예 상한은 유지했습니다. 늦게 새로 생긴 소실·다른 ID·오류는 즉시 중단합니다.
2. 다음 실기에서는 기준 조건이 통과했지만 종료 뒤 화면이 원래 기준에서 22px 이상 달라 후보 조건을 시작하지 않았습니다. 두 조건의 시작 위치 제한을 풀지 않았습니다.
3. 수정 조건만 새 기준 화면에서 별도로 검사해 통과했습니다. 따라서 위 표는 서로 다른 실기 구간의 동작 기록입니다. 실패·부분 결과·RAW16 총 601장을 비공개 보존했습니다.

## 서버 확인과 남은 범위

배포 소스와 시험 소스가 일치하고 브리지 바이너리 해시가 일치했습니다. 재시작 후 28초 시점에 정상 관측 572건, 차단 관측 46건을 확인했습니다. 차단에는 초기 카메라 반복 프레임이 포함됩니다. 카메라·브리지 정상, 연결 오류 0, 큐 교체 7장, 입력 간격 이상(`gaps`) 0, 예측 꺼짐을 확인했습니다. 기존 keepalive 일시중지와 8770은 유지했습니다.

짧은 입력 누락 연결은 검증했지만, 사람의 실제 급이동·근거리·가림·세로 축에서 중심 유지와 화면 흔들림이 좋아지는 정도는 아직 확인하지 않았습니다. 동일 ID가 항상 동일 인물이라는 보장도 이 기능이 제공하지 않습니다. 최종 움직임 품질은 같은 실제 장면의 전후 비교로 추가 확인해야 합니다.
