# 예측 제어의 기준점과 지연 점검

목표는 선택한 대상을 화면 중앙의 허용 범위 안에 유지하면서 불필요한 카메라 왕복과 속도 변화를 줄이는 것입니다. 대상의 빠른 이동을 무조건 억제하거나, 카메라 총 이동량 하나만 최소화하지 않습니다.

## 이번 수정의 범위

예측과 PD가 같은 관측 지점을 사용하도록 연결을 고칩니다. 기존 예측은 사람 박스의 중심을 사용하지만, PD의 세로 기준은 `y + aim_y * height`입니다. 박스 높이가 바뀌면 두 지점이 다르게 움직입니다. 이 수정만으로 가림 때문에 생기는 박스 변형을 실제 신체 움직임과 구분할 수 있게 되는 것은 아닙니다.

화면 안정화가 켜졌을 때도 좌표를 일치시켜야 합니다. GMC는 검출용 캔버스의 이전 영상에서 현재 영상으로 가는 변환입니다. 짐벌에는 화면 보정이 제거된 카메라 좌표가 전달됩니다. 두 좌표 사이의 보정과 캔버스의 위쪽 16행을 빠뜨리면, 예측에 가짜 움직임이 생길 수 있습니다.

실제 브리지에 전달하는 박스와 실행 인자를 기준으로 예측합니다. 설정이나 좌표가 확인되지 않으면 예측 보정은 사용하지 않으며, 유효한 관측 행의 전달은 유지합니다. 기존 정지·소스 변경·ID 변경·재생 차단 규약은 유지합니다. LEAD의 기본값은 계속 꺼짐입니다.

## 지연을 반영한 다음 설계

고정된 시간에 대상 속도를 곱하는 것만으로 실제 카메라의 미래 화면을 설명할 수 없습니다. 같은 카메라 좌표에서 예측해야 할 값은 다음과 같습니다.

`미래 화면 오차 = 현재 관측 오차 + 예상 대상 이동 - 예상 카메라 회전에 의한 영상 이동`

여기서 시간은 이전 프레임과의 간격뿐 아니라 해당 영상의 수신 이후 경과 시간, 처리·전달 시간, 이미 보낸 명령의 효과를 포함해야 합니다. 센서 노출 시각을 모르는 경우 수신 시각을 노출 시각이라고 부르지 않습니다. 카메라 반응 모델이 아직 검증되지 않았다면 수치를 추측해 운영 제어에 넣지 않습니다.

예측 보정은 기존 D항과 함께 설계해야 합니다. 화면 변화율을 P항의 선행 위치와 D항 양쪽에 사용하면 보정과 잡음의 크기가 함께 바뀝니다. D항을 무조건 없애거나 그대로 둔 채 예측 시간만 늘리는 대신, 같은 관측과 제약에서 효과를 분리해 확인합니다.

두 축에 공통 SPD를 쓰는 장치 제약도 남아 있습니다. 가로 단독 저속 시험으로 세로·대각선·전체 운영 속도 범위의 안정성을 입증하지 않습니다.

## 판정 기준

- 같은 표적 경로와 중심 허용 범위에서 중심 오차, 범위 이탈 시간, 급정지 후 정착과 넘침을 비교합니다.
- 필요한 추종 이동과 불필요한 왕복·잔떨림을 구분합니다. 총 이동량 증가는 그 자체로 실패 판정이 아닙니다.
- 관측 누락·동결·급반전·근거리 박스 변형을 따로 확인합니다.
- 저장 기록은 지연 식별과 실패 분석에 사용합니다. 과거 제어로 찍힌 영상을 재생한 결과를 새 제어기의 실제 폐루프 성능이라고 부르지 않습니다.
- 실제 구동은 현장 조건을 확인한 뒤 별도 제한 비교로 진행합니다. 최초 로컬 수정 당시 서버·장치 설정은 바꾸지 않았으며, 이후 적용 상태는 아래와 같습니다.

## 검증 결과

Windows에서 `test_predictive_lead`, `test_live_tracks`, `test_observation_transport`의 42개 검사가 통과했습니다(기존 37개, 추가 5개). 추가 검사는 박스 높이 변화와 고정 추종점, 기준점 변경 시 초기화, 무효 입력, 실행 인자의 마지막 `--aim-y` 우선 적용, 회전·이동 GMC와 프레임별 화면 보정, 실제 전송되는 소수점 박스와 원본 그림의 보존을 확인합니다. `git diff --check`도 통과했습니다.

브리지의 새 응답을 추가한 것은 아닙니다. 기존 LEAD 지원 응답을 받은 프로세스의 실제 실행 인자를 읽으며, 웹 화면에 남은 설정값이나 별도 기본값으로 추정하지 않습니다. C++ 제어기·PD 이득·속도 제한·정지 규약은 바꾸지 않았습니다.

이 결과는 코드의 좌표 일치와 회귀 검증입니다. 이후 사용자 지시로 `52a0995`를 main과 장치에 적용했습니다. ARM64에서도 같은 Python 검사 42개를 통과했고 8090 정상 재시작, 영상·브리지·OBS 상태를 확인했습니다. 기존 C++ 바이너리와 설정을 유지하며 LEAD는 꺼져 있습니다. 사람이 움직이는 영상에서 중심 유지·잔떨림이 개선됐다는 결과는 아직 없습니다. 제동 모델과 전체 속도 범위 튜닝 완료로 해석하지 않습니다.

저장된 실제 시험 4세션의 압축본 해시, RAW16 2,183장 헤더·시각, 기존 영상 정합 1,520건과 제어 trace 1,327행을 대조했습니다. 분석기 검사 5개가 통과했습니다. 영상 픽셀에서 정합을 새로 계산한 결과는 아닙니다.

급이동 시험에서 첫 이동 명령 뒤 배경 1px 이동이 관측된 시각 구간은 119.5–184.5ms였습니다. 이는 직렬 쓰기 직전부터 영상이 호스트에 도착할 때까지의 관측이며, 노출·전송·샘플링과 여러 후속 속도 명령이 섞여 있습니다. 고정 모터 지연값으로 사용할 수 없습니다. STOP 직후 반대 명령이 나온 구간은 단독 제동 분석에서 제외했습니다.

마지막 작은 흔들림 입력 구간의 수평 영상 이동은 기존 0.165px, 후보 0.121px였고 두 조건 모두 새 이동 명령이 없었습니다. 따라서 앞선 전체 이동량 약 4.8% 증가는 잔떨림 악화를 입증하지 않습니다. 실제 사람·반복 시험·전체 속도 범위의 우위 역시 입증하지 않습니다.

이후 가로 SPD 1·7의 양방향 고정 명령→단독 STOP 네 조건을 실제로 완료했습니다. [후속 측정 결과](FIXED_PULSE_RESULT_20261112_KO.md)에서 명령→영상 반응 구간과 정지 후 영상 이동을 확인할 수 있습니다. 센서 노출 시각과 명령 적용 시각 또는 독립적으로 동기화한 영상·각속도는 여전히 확보하지 못했습니다. 각 조건 한 번의 저속 가로 자료만으로 속도 상한 100의 세로·대각선 모델을 추정해 배포하지 않습니다.
