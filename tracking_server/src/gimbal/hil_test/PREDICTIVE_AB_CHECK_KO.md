# 새 예측 제어의 첫 실제 비교

목적은 선택한 사람의 중심 이탈을 줄이면서 화면 이동과 방향 반전, 대상 놓침을 늘리지 않는지 확인하는 것이다. 정지 영상 점검이나 가상 직렬 포트 시험을 실제 추종 성능으로 해석하지 않는다.

## 비교 조건

- Python의 관측 박스와 별도 `LEAD` 보정, `CONTROL_EPOCH`를 처리하는 새 v27을 함께 사용한다. 예측 끔과 켬 모두 같은 수정본이다.
- 첫 후보는 기존 설정인 **150 ms 하나**다. 양쪽 모두 Kp30/Ki0/Kd6, 불감대0.06, 조준 높이0.08, 동일 추적기로 비교한다. 첫 비교의 자동 최고 속도는 과거 실측 범위인 **10으로 양쪽을 똑같이 제한**한다. 현재 운영 상한100의 개선을 입증하는 시험이 아니며, 고속 범위는 중단된 특성 시험의 원인을 해결한 뒤 별도 검증한다. 비교 도중 이득이나 속도 제한을 바꾸지 않는다.
- 현재 프로세스의 실제 인자를 비교 전에 보관한다. 과거 문서에 있던 `--deadband-exit` 또는 `--axis-reversal`이 지금도 적용됐다고 가정하지 않는다.
- 운영자가 같은 시작 구도에서 같은 짧은 이동과 정지를 수행한다. 첫 한 쌍은 예비 점검이며, 한 번 좋았다는 이유만으로 최적 설정이나 일반적인 개선을 주장하지 않는다.
- 이전 1단계가 중단된 원인은 아직 실제 이동과 영상 정합 오류로 구분되지 않았다. 이 단계가 통과한 것으로 취급하거나 기존 전체 계획을 자동 재시작하지 않는다.

## 시작 전에 확보할 것

1. 짐벌 옆에 사람이 있으며 정지 조작 및 서보 전원 차단 위치를 확인한다. 브리지 교체도 이 조건이 필요하다.
2. 카메라·직렬 포트의 소유 프로세스를 확인하고 기존 설정, 프로그램과 복구 명령을 보존한다. 다른 서버와 작업은 그대로 둔다.
3. 정지 영상에서 영상 정합을 확인한다. 화면과 사람이 잘려 있거나 주 추종점을 판단할 수 없는 장면을 정상 튜닝 입력으로 선택하지 않는다.
4. 같은 프레임 번호·시간에 관측 추종점, 전달된 예측값·선택 세대, 브리지에서 실제 적용 여부, 직렬 이동·정지 명령을 기록할 수 있어야 한다.
5. 정합과 독립적으로 움직임을 대조할 고정 표지 또는 정지 전후 원본 영상을 확보한다. 명령 적분 위치는 실제 각도 측정이 아니다.

기존 `lead_hil.py`는 박스를 옮기는 옛 경로이고 자동 복구·재시도도 포함한다. **이 파일을 그대로 실행해 새 경로를 검증하면 안 된다.** 새 경로 기록이 준비되지 않았다면 성능 비교를 시작하지 않는다. 단순 HTTP 조회로 따로 받은 이미지와 상태도 같은 프레임의 기록으로 취급하지 않는다.

## 중단과 결과 보존

영상 정합 급변·품질 불가, 영상 동결·지연, 대상 상실, 변위 한계 초과 또는 정지 확인 실패가 발생하면 정지하고 이번 비교를 끝낸다. 자동 복구와 동일 조건 자동 재시도는 하지 않는다. 실패 직전·중단 시점·정지 뒤의 원본 영상과 시간을 남긴다. 정지 명령이 기록된 것과 실제 정지는 구분한다.

## 읽을 지표

| 지표 | 집계 범위 |
|---|---|
| 가로·세로 중심 절대오차 중앙값과 p95 | 관측 추종점이 있는 구간. 예측으로 이동시킨 점을 정답처럼 쓰지 않음 |
| 대상 놓침 비율과 최장 연속 놓침 | 좌표 없는 기록도 포함한 전체 시험의 기록된 시간. 첫 기록 앞·마지막 기록 뒤는 외삽하지 않음 |
| 화면 누적 이동, 이동 속도 변화 | 유효 정합 구간과 커버리지를 함께 보고. 중심 오차의 흔들림과 별도 |
| 방향 반전과 정지·재시작 | 실제 직렬 명령과 시간 기준. 한 축의 변화가 다른 축을 움직이는지도 확인 |
| 시험 종료와 실제 정지 | 마지막 명령, 영상, 현장 관찰을 대조 |

중심 오차가 줄어도 놓침이나 화면 이동이 늘면 그대로 채택하지 않는다. 관측 부족·타임라인 오류·중단 구간은 성공으로 합치지 않는다. 첫 비교는 뒤따를 이득 조정의 근거를 마련하는 단계이며, 물리적 개선이 확인되기 전에는 ‘튜닝 완료’로 기록하지 않는다.
