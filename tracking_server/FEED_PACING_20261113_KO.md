# 교대 대기 알림과 녹화 시간표 적용 결과

2026-11-13. 코드 `fec1976`을 장치 8090에 적용했습니다. 기본 교대와 비동기 미리보기를 유지하고, 장치에서는 `LWIR_REPLAY_PACING=deadline`을 켰습니다. 코드 기본값은 비교 가능한 `legacy`입니다.

## 바뀐 부분

- 교대 제출 대기열에서 현재 작업을 꺼내 빈 자리가 생기면 대기 중인 제출 스레드에 즉시 알립니다. 기존 코드에서는 빈 코어와 다음 입력이 있어도 현재 코어의 결과를 받을 때까지 기다리는 경우가 있었습니다. 결과 수집 순서는 유지합니다.
- 채점용 무손실 녹화의 읽기·전송 시간을 프레임 주기에 포함합니다. 이전에는 작업 뒤에 매번 한 주기를 더 기다렸습니다. 한 주기 이상 지각하면 새 시간표를 잡으며, 프레임을 건너뛰지 않습니다. 물리 카메라 공급 속도에는 영향을 주지 않습니다.
- 재생 시작 API의 `pacing=legacy|deadline`으로 같은 서버에서 비교할 수 있습니다. 상태와 평가 기록에 선택값을 남기며 다시 계산에도 유지합니다. 라벨 없는 건너뛰기 재생은 기존 시간표이므로 실제 로그의 `lossless on`도 확인해야 합니다.

## 비교 조건과 범위

같은 16비트 녹화 212장·사람 GT 829개·30fps 요청으로 기존 버전 2회, 새 코드 legacy 2회, 같은 새 서버 deadline 2회를 수행했습니다. 입력 PNG 212개·라벨·검수 파일·실행 코드의 해시와 모델·추적·제어 설정을 기록했습니다. 전체 장을 채점하고 JPEG도 모두 발행했으며 동영상 파일을 새로 저장하지 않았습니다.

각 측정 전 31초 동안 입력이 없고 JPEG 지연 통계 창이 비었는지 확인했습니다. 다만 기존 버전은 계측용 시청자 외 1명, 새 legacy는 0명, deadline은 첫 회 0명·둘째 회 1~2명이었습니다. **여섯 회차의 조건이 모두 같지는 않습니다.** 아래 전체 수치는 관측값이며 깨우기 수정만의 개선율로 해석하지 않습니다. 모델·선택 설정·입력·채점은 여섯 회차가 같았습니다.

### 전체 회차의 관측값

각 조건은 2회 합계 424프레임, 출력 간격은 회차 경계를 제외한 422개입니다. 평균/p95는 내보낸 반올림 행을 합쳐 선형 보간으로 계산했습니다.

| 입력→추적 결과 | 평균 ms | p95 ms |
|---|---:|---:|
| 기존 버전 legacy | 56.86 | 87.45 |
| 새 코드 legacy | 46.12 | 55.77 |
| 새 코드 deadline | 42.12 | 54.14 |

| 추적 결과 출력 간격 | 평균 ms | p95 ms |
|---|---:|---:|
| 기존 버전 legacy | 35.96 | 53.39 |
| 새 코드 legacy | 35.37 | 52.58 |
| 새 코드 deadline | 33.32 | 50.59 |

기존 두 회차의 추적 지연 p95는 90.61/55.63ms로 차이가 컸습니다. 배포 전후의 서버 재시작, 실행 순서, 온도와 실행 부하 영향을 배제하지 못하므로 전체 표의 감소량을 전부 수정 효과로 돌리지 않습니다.

### 같은 서버·접속 조건의 참고 비교

성능 수치가 아니라 **활성 JPEG 구간의 외부 시청자가 0명이었던 조건**으로 고르면 새 legacy 두 회차와 deadline 첫 회가 해당합니다. 세 회차 모두 계측용 시청자는 1명입니다. 단, deadline은 이 조건에서 한 번뿐입니다.

| 지표 | legacy 평균 / p95 ms | deadline 평균 / p95 ms |
|---|---:|---:|
| 서버 입력→추적 결과 | 46.12 / 55.77 | 42.18 / 54.40 |
| 추적 출력 간격 | 35.37 / 52.58 | 33.27 / 52.30 |
| 복원한 서버 입력 간격 | 35.34 / 40.41 | 33.29 / 38.88 |

전체 표본은 424장→212장, 간격은 422개→211개입니다. 입력 간격은 `출력 시각 차이 - 프레임 지연 차이`로 복원한 근삿값입니다. 앞뒤 10장씩 제외해도 출력 간격 평균은 35.31→33.22ms였지만 p95는 52.16→52.60ms였습니다(384장→192장, 382간격→191간격). 평균 공급 속도는 요청한 30fps에 가까워졌으나 높은 지연의 꼬리는 개선됐다고 말할 수 없습니다.

서버 JPEG 준비 p95는 전체 각 회차 순서로 기존 108.8/78.7ms, 새 legacy 76.0/75.6ms, 새 deadline 78.9/73.0ms였습니다. 이는 각 회차의 통계이며 서로 합친 p95가 아닙니다. 같은 접속 조건의 deadline 첫 회는 78.9ms로 legacy보다 나빠졌습니다. JPEG 지연의 일관된 개선은 확인되지 않았습니다.

## 검증·운영 상태

- PC 97개, ARM64 격리 후보 검사 97개 통과. 장치 검사는 기존 서버를 종료하기 전에 수행하고 배포 파일과 검사한 소스의 해시를 대조했습니다.
- 기존 코드의 깨우기 누락은 PC에서 재현했습니다. 수정 후 두 번째 코어 제출이 첫 번째 결과 수신에 막히지 않고 출력 순서가 보존됐습니다. 별도의 현장 단독 개선량은 미확인입니다.
- 초기 계측은 접속자 수 변화로 0회차에서 중단했습니다. 실패 기록을 보존하고 도구의 연결 종료 및 접속자 기록을 수정한 별도 비교에서 여섯 회차를 완료했습니다. 실패를 완료 회차로 세지 않았습니다.
- 실제 재생 로그의 `pacing deadline, lossless on`을 확인했습니다. 8090의 두 엔진 교대·비동기 미리보기와 기존 모델·v27 바이너리/제어값을 유지했습니다. 8770 프로세스의 생성 시각과 인자가 같습니다.
- 시험용 재생·측정은 끝내고 원래 보던 녹화와 23fps 설정을 복원했습니다. 이전 위치 값은 없었으므로 처음부터 재생했습니다. 짐벌 자동 추종·예측 제어는 꺼져 있으며 실기 튜닝을 재개하지 않았습니다.
- 카메라 USB는 확인 시 목록에 없었습니다. 이 측정은 **저장 영상의 서버 도착→결과/JPEG 준비** 범위이고 센서·USB·브라우저 표시 지연은 포함하지 않습니다.

**판정:** 수정은 적용했고 전체 프레임과 점수는 보존했습니다. 녹화의 평균 출력 간격은 약 33.3ms에 도달했지만, 프레임 지연 및 출력 간격 p95 33.3ms 목표는 미달입니다. 실카메라 30fps 또는 끝단 지연 달성으로 주장하지 않습니다.
