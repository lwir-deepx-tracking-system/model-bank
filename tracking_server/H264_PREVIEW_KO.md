# H.264 화면 시험

8090 화면의 `화면` 메뉴에서 `H.264 (고화질 시험)`을 고르면 별도 미리보기 서버를 사용합니다. 기본값은 기존 JPEG이며 서버 연결 실패 시 JPEG로 돌아갑니다. 영상은 JPEG 미리보기를 640×480으로 변환하고 Rockchip MPP로 목표 비트레이트 4Mbps로 다시 인코딩합니다. 앞 단계 JPEG의 손실을 되돌릴 수 없고, 검출기와 추적기의 입력은 바꾸지 않습니다.

화면에 박스가 별도 전송되는 모드에서는 박스와 영상이 시간상 정확히 일치한다고 보장할 수 없습니다. 따라서 H.264 화면에서는 사람 클릭 선택을 막습니다. 사람을 선택할 때는 JPEG로 전환해야 합니다. H.264 화면의 카메라-화면 지연은 아직 측정하지 않습니다. H.264가 JPEG보다 빠르다는 주장이나 33ms 달성 주장은 없습니다.

동시 시청은 최대 두 명입니다. 이미 두 명이 사용 중이면 JPEG로 돌아갑니다. 8090과 별도로 18774 포트가 필요합니다. `scripts/run_real_gui.sh`는 사용 가능한 경우 미리보기 서버도 시작합니다. 단독으로 다시 켜려면 `bash tracking_server/scripts/start_h264_quality.sh`를 실행하고 `tracking_server/h264_quality.out`을 확인합니다. 이 스크립트는 이미 점유된 포트의 프로세스를 종료하지 않습니다. 노출 범위는 기존 추적 서버의 Tailscale 주소를 따릅니다.

테스트: MPP 하드웨어 인코더로 실제 카메라 프레임을 H.264로 변환하고 PC Edge로 8090 화면에서 재생했습니다. 약 8초 동안 두 창이 동시에 재생했고 확인 시점 카메라·추적 FPS는 각각 30이었습니다. 장시간 재생, 모바일 브라우저, 화면 도착까지의 지연과 영상-박스 시차는 아직 검증하지 않았습니다. 안정적인 프레임 동기화 없이는 H.264에서 추적 대상 클릭을 켜지 마세요.
