# MOTIP 인계 — 원본 모델을 우리 추적 화면에서 시험하기

**2026-11-13 현재: 시험 중이며 GUI에 연결되지 않았습니다.** 이 폴더는 실행 중인 서버 코드가 아닙니다. 사용자의 최신 지시는 **MOTIP을 먼저 해결**하고, FastTrackTr은 나중에 공식 데이터로 학습해 비교하는 것입니다. MOTIP 파인튜닝은 일단 하지 않습니다.

## 결론과 가장 중요한 문제

- 원본 MOTIP의 검출·ID 모델을 읽어 PC에서 연속된 열영상 2장을 처리했습니다. ID 0이 두 장에서 유지됐습니다. 단 2장이라 가림 뒤 ID 유지의 근거는 아닙니다.
- 640×480 영상 특징 추출부를 M1 DXNN으로 변환하고 4장을 실행했습니다. 호스트가 요청하고 특징을 받을 때까지 **108.169 / 90.638 / 55.169 / 60.759ms**였습니다. 초기 호출 포함 4회이며, **이 부분만** 33ms를 초과했습니다. 후단·ID·카메라·화면은 포함하지 않습니다. 전체 모델 실시간 성능이나 p95가 아닙니다.
- 검출기 전체를 한 번에 DXNN으로 만드는 시도는 실패했습니다. 원본 변형 없이 전체를 M1에 올렸다고 주장하면 안 됩니다. 자세한 결과는 아래 3절.
- 현행 모델 목록은 YOLO용 DXNN 입력·출력만 받습니다. MOTIP은 과거 상태와 별도 ID 처리도 필요하므로, 파일을 모델 폴더에 넣는 것만으로 GUI에서 작동하지 않습니다.
- **기존 8090·8770·짐벌 설정은 이 연구로 변경하지 않았습니다.** 임시 장치 시험은 별도 폴더를 사용했습니다. 팀원이 사용하는 동안 장치 자원을 중복 사용하거나 기존 서버를 임의로 종료하지 마세요.

## 다음 작업 순서

1. **특징 추출의 시간 분해:** M1이 사용 가능할 때 같은 조건으로 NPU 계산·입력 전송·세 특징맵 출력 수신을 따로 측정합니다. 세 출력은 640×480 입력에서 FP32 기준 합계 약 17.2MB/장입니다. 이 양은 텐서 크기 계산이며 실제 전송 비용은 아직 미측정입니다.
2. **검출 후단 검증:** 같은 프레임에서 NPU 특징을 CPU 후단에 넣고 원본과 박스·점수 차이, 프레임 지연을 확인합니다. 현재는 특징을 PC로 가져와 후단을 실행한 예비 비교만 했습니다.
3. **ID 상태:** 첫 프레임, 인원 증감, 가림과 재등장, 최대 용량 초과, 재생 되감기/리셋을 원본과 대조합니다. ID head 고정형 합성 테스트만으로 실제 이력 관리까지 같다고 보면 안 됩니다.
4. **GUI:** 실제 백엔드가 프레임·박스·점수·ID를 기존 화면에 제공하고 중단/전환 시 상태를 정리하는지 먼저 시험합니다. 사용할 수 없는 메뉴를 작동하는 것처럼 넣지 않습니다. 동작 확인 뒤에만 녹화와 실시간 경로, 장치 적용을 검토합니다.
5. **공정 비교:** 같은 영상·GT·무시 영역·프레임에서 기존 YOLO26m+ByteTrack 및 MOTIP의 FP/FN, 한 명→여러 ID, IDSW·IDF1·HOTA와 처리시간을 비교합니다. 실카메라와 화면까지의 지연, 출력 간격 p95도 별도 확인합니다.
6. **후순위 FastTrackTr:** 사용자는 공식 데이터로 학습하는 방안을 허용했습니다. 전체 추적 가중치는 아직 찾지 못했습니다. [가중치 요청](https://github.com/liaopan-lp/fasttracktr/issues/2)이 열려 있고, 저장소 README의 Apache 2.0 문구와 실제 `LICENSE.txt`의 GPL-3.0이 달라 사용·배포 전에 확인해야 합니다. 해당 학습은 아직 시작하지 않았습니다.

## 3. 실제로 한 시험

### 원본과 입력

- [공식 MOTIP 코드](https://github.com/MCG-NJU/MOTIP) 커밋 `ffc0e90`, [DanceTrack v0.1 가중치](https://github.com/MCG-NJU/MOTIP/releases/download/v0.1/r50_deformable_detr_motip_dancetrack.pth), 709,007,050바이트. 받은 파일의 SHA-256: `c642793c1f3d526aa8537d59bc6a3d201b44b16099076519ffad5ec379050800`. 공식 측 별도 해시와의 일치는 미확인입니다.
- 체크포인트에서 모델 텐서 719개를 `weights_only=True`로 추출해 `strict=True`로 로드했습니다. 공식 CUDA 확장 대신 공식 코드의 PyTorch 참조 연산을 사용했습니다. 참조 연산과 공식 CUDA 확장 사이의 수치 대조는 하지 않았습니다.
- 640×480의 8비트 저장 영상 앞 2장: 각각 후보 1개, ID 0→0, 점수 약 0.942/0.944. 16비트 두 장은 시험용으로 `//256` 후 임계값 0.5에서 후보가 없었습니다. 변환 차이, 영상 조건, 모델 한계 중 원인은 미확인입니다. 이 시험을 카메라 전처리 기준으로 확정하지 마세요.

### 변환·M1

- 640×480 검출기 전체를 고정 입력 ONNX로 내보내 PC의 원본 참조 연산과 비교했습니다. logits·박스·특징 최대 절대오차는 각각 약 `2.91e-5`, `1.73e-6`, `2.15e-5`. 정밀도 허용 범위 내입니다. 추적 ID는 여기에 포함되지 않습니다.
- 세 ResNet 특징맵으로 그래프를 나눈 뒤 float ONNX를 다시 연결했을 때 같은 합성 입력의 검출 출력은 **완전히 일치**했습니다. NPU INT8 출력이 완전히 일치했다는 뜻은 아닙니다.
- 실제 저장 영상 8장으로 특징 추출부를 진단 보정하고 같은 시퀀스의 다른 네 장을 시험했습니다. NPU 특징+PC float 후단과 float 기준은 점수 0.5 초과 쿼리가 네 장에서 같았지만 특징·박스 수치는 달랐습니다. 8비트 2장은 각 1개, 16비트 `//256` 2장은 각 0개였습니다. 서로 가까운 프레임이라 독립 일반화나 GT 정확도 결과가 아닙니다.
- DX-COM `2.4.1-rc.1`: 전체 128×160 검출기의 기본 분할은 `NoWeightOperationsError`. aggressive 분할은 NPU 14·CPU 19개 그룹으로 나뉜 뒤 보정 중 `UnknownError`. 작은 ID 헤드도 기본 분할 실패, aggressive는 NPU 1·CPU 1 그룹 뒤 보정 `UnknownError`. 특정 연산의 지원 여부를 이 오류만으로 단정하지 않습니다.
- ID 이력은 최대 29프레임·50 ID·50 후보의 고정형에 마스크를 적용한 synthetic 5조건에서 원본 가변 PyTorch와 ONNX의 유효 점수 차이가 최대 `8.71e-6` 이내였습니다. 상태 갱신·50 후보 초과·실영상 가림·NPU는 미검증입니다.

### 결과 해석 주의

8장 보정, 4장 평가는 기능을 보는 작은 시험입니다. 두 시퀀스와 주변 프레임이 겹치고, 미세 객체·가림·오탐과 지연 p95를 평가하지 않았습니다. `//256`은 이 시험의 입력 처리일 뿐 실제 카메라의 RAW16 전처리 정답이라고 확인된 것이 아닙니다.

## 4. 코드와 실행 준비

이 폴더의 코드는 **실험용**입니다. 외부 라이브러리·가중치·데이터와 결과물은 이 공개 저장소에 넣지 않았습니다. 사용자 또는 기존 비공개 저장소에서 경로를 확인해 환경변수로 지정하세요.

| 환경변수 | 내용 |
| --- | --- |
| `MOTIP_UPSTREAM` | 공식 MOTIP 저장소를 별도 복제한 폴더 |
| `MOTIP_ARTIFACTS` | 가중치·ONNX·컴파일 결과를 보관할 별도 폴더 |
| `LWIR_SOURCE_ARCHIVE` | 사용 권한이 있는 비공개 영상/라벨 ZIP |

PC에서 Python 3.10 이상, PyTorch·torchvision·ONNX·ONNX Runtime·OpenCV·accelerate·einops·scipy 등을 사용합니다. 실험에는 Python 3.10 / PyTorch 2.1.2와 체크포인트 추출용 PyTorch 2.7을 사용했습니다. 체크포인트 추출은 `weights_only=True`를 지원하는 환경에서 실행합니다. 공식 CUDA 확장이 없어도 일부 실험은 참조 연산을 사용합니다.

```bash
# 개인 환경에서 위 세 환경변수를 먼저 설정한다.
python prepare_model_only.py
python attention_onnx_preflight.py
python motip_reference_smoke.py --sequence seq_001 --shorter 480
```

`prepare_model_only.py`는 공식 파일의 위 SHA를 확인하고 모델 텐서만 별도로 저장하며, 기존 파일을 덮어쓰지 않습니다. 환경마다 명령·패키지 설치는 달라질 수 있습니다.

주요 스크립트:

- `motip_detector_onnx_probe.py` → `motip_backbone_extract.py` → `motip_split_remainder.py`: 검출부 고정 그래프와 분리 동등성. 640×480은 `MOTIP_PROBE_H=480`, `MOTIP_PROBE_W=640`으로 지정합니다.
- `prepare_backbone_raw_probe.py` → `backbone_raw_dxcom_probe.py`: 비공개 영상의 8장 진단 보정과 부분 컴파일. 원본 데이터는 수정하지 않지만 작업 결과를 새 폴더에 씁니다.
- `motip_npu_backbone_probe.py`, `motip_npu_vs_float.py`: M1 출력과 PC float 후단 비교. 장치 사용 가능 여부를 먼저 확인하고 기존 서버와 충돌하지 않게 실행합니다. 장치 스크립트는 시험 파일을 스크립트와 같은 별도 폴더에서 읽습니다.
- `motip_id_padding_preflight.py`, `motip_id_padded_onnx_preflight.py`: 고정 용량 마스크 확인. `MOTIP_ID_BIG=1`은 29/50/50 예시입니다.
- `detector_dxcom_probe.py`, `id_dxcom_probe.py`, `attention_dxcom_probe.py`: 실패 원인 분석용. 결과 폴더가 있으면 덮어쓰지 않으며, aggressive 재시험은 `MOTIP_AGGRESSIVE_PARTITIONING=1`입니다.

이 폴더에 공개한 것은 **경로만 환경변수로 바꾼 연구 코드**입니다. 모든 스크립트를 다시 실행한 것은 아닙니다. 이 복사본에서 ONNX attention 수치 시험, ID 패딩 5조건, 640×480 저장 영상 2장의 ID 0→0만 재검증했습니다. 원본 로그와 비공개 데이터 위치는 사용자에게 별도로 전달받으세요.

MOTIP 코드·가중치의 저작권과 라이선스는 [공식 저장소](https://github.com/MCG-NJU/MOTIP)를 따릅니다. 이 폴더는 공식 프로젝트를 포함하거나 대체하지 않습니다.
