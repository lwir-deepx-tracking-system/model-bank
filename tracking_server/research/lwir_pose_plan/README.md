# 열화상 사람 자세 모델 학습 계획 (2026-11-15)

근거리와 원거리를 한 모델(YOLO26m-pose, 머리~엉덩이 몸 상자)로 처리하고, 가려진 사람(책상·모니터 뒤, 화면 밖으로 잘림)에 강하게 만든다. 겨누는 점은 얼굴과 가슴 사이, 장치(DX-M1 INT8)에서 실시간.
지금 장치에 있는 판: `models/detect/yolo26m/yolo26m_pose_otp2cocomot_20261114_bodybox_occl*_640x480` (= 실험 E).

## 1. 학습 단계

| 단계 | 자료 | 이유 | 상태 |
| --- | --- | --- | --- |
| 1 기초 | 공개 COCO 컬러 자세 모델에서 시작, 흑백으로 바꾼 COCO·MOT17 을 섞음 | 몸 모양은 컬러 자료가 가장 많음. 흑백은 우리 입력(회색 1장을 3채널로)과 같은 모양. MOT17 은 가림이 많음 | 끝남 (실험 E) |
| 1 선택 | KAIST 또는 우리 컬러 카메라 짝: 컬러에서 찾은 관절을 열화상으로 옮긴 정답 | LLVIP-Pose 시험용으로 확인: 밝은 장면에서 사람 99% 찾음, 관절 96%가 키의 10% 안 | 필요할 때 |
| 2 열화상 | OTP2 + LLVIP-Pose + 흑백 자료 계속 + 가림 합성 | 열화상은 모습이 달라 진짜 열화상으로 다시 배움. LLVIP-Pose 는 중·원거리, 가림 합성은 책상 뒤 사람 | 진행 중 (R0 대조, R1 + LLVIP-Pose) |
| 3 우리 카메라 | 손 라벨(모델이 먼저 달고 사람이 고침) + 자기 학습(가린 구간은 앞뒤 프레임으로 메움) + 원거리 자료 조금 + 가림 합성 | 쓰는 카메라 라벨이 효과가 가장 큼(UPPET). 원거리 자료는 원거리 유지용 | 준비 중 |
| 4 장치 | 결승 모델 INT8 변환, 장치에서 채점 | PC 이득이 장치에서 남아야 씀 | — |

하지 않음: 흑백만 따로 학습하는 단계(LLVIP-Pose 에서 컬러/흑백 시작 차이 0.1점 수준), TMOT 컬러 짝으로 관절 옮기기(컬러와 열화상의 사람 번호가 다름), 컬러→열화상 그림 변환(근거 없음).

## 2. 학습 설정과 이유 (2026-11-15 근거 조사: 우리 학습 곡선, 프로젝트 기록, 노션, 문헌)

**결론:** 설정은 대부분 그대로 둡니다. 꼭 고칠 것은 세 가지입니다.

1. **조기 멈춤을 끄고, 다음 단계에는 마지막 가중치를 넘깁니다.** 지금 멈춤 기준에는 몸 상자 점수가 섞여 있는데, 이 점수가 에폭마다 크게 흔들립니다. 그래서 관절 점수가 아직 오르는 중에 학습이 멈췄고, 더 나쁜 가중치가 골라졌습니다. 장치에 있는 실험 E도 이 더 나쁜 4에폭 판입니다. 체크포인트 안의 점수로 직접 확인했습니다(OTP2 관절 0.81, 마지막 에폭 판은 0.85).
2. **이미 다듬은 모델에서 다시 시작할 때는 학습률을 2e-4에서 1e-4로 낮춥니다.**
3. **3단계는 회차마다 2단계 승자에서 시작합니다.** 적응시킨 모델을 다시 적응시키지 않습니다.

### 2-2. 지금 계획에서 바뀌는 것

1. 모든 자세 학습에서 조기 멈춤을 끄고(patience 0), 다음 단계에는 last.pt를 넘깁니다. 멈춤 기준에 상자 점수를 계속 쓰려면, 그 전에 몸 상자 평가를 고칩니다. 정답과 예측을 같이 자르거나 둘 다 자르지 않거나, 아니면 기준을 관절 점수만으로 바꿉니다.
2. R1은 patience 4로 도는 중입니다. 손대지 않고 두되, 일찍 멈추면 R0와 에폭 수가 달라지므로 patience 0으로 다시 돌립니다.
3. R0·R1 채점에 E의 last.pt를 기준선으로 추가합니다. 지금 채점은 E의 4에폭 판만 씁니다.
4. 새 가림 학습은 승자의 last.pt에서 학습률 1e-4로 시작하고, 새 가림만 뺀 대조 갈래를 붙입니다. GPU 시간이 약 3시간 늘어납니다.
5. 3단계: 회차마다 2단계 승자에서 시작, 우리 자료와 2단계 자료를 반반, 손 라벨 3배, 한 에폭이 짧으면 워밍업 2에폭.
6. FastTrackTr: 짧은 워밍업과 매 에폭 TMOT 검증을 넣고, 실행 설정의 에폭 수를 확인합니다.
7. 계획 글에서 틀린 설명을 고칩니다.
   - 처음 무너진 자동 설정 학습에는 바이어스 0.1 워밍업이 없었습니다(자동 모드가 0으로 바꿈). 실제 원인은 학습률 0.002(지금의 10배)였습니다.
   - "5e-4로도 무너졌다"는 근거는 워밍업 없는 1에폭 시험 하나뿐이고, 그 시험에서 가림 보강도 처음 켰습니다.
   - 학습률은 0.1배가 아니라 약 0.2배까지만 내려갑니다.
   - 흑백 MOT17은 1천 장이 아니라 2,536장입니다.
   - 계획에 적힌 OTP2 관절 약 0.85는 E의 마지막 판 숫자입니다. 장치에 있는 E는 4에폭 판이라 OTP2 검증에서 0.81입니다.
   - 가중치 감쇠는 사실상 꺼져 있다고 적습니다.
   - 모자이크를 끈 이유를 적습니다.

## 6. 세부 규칙 (자료 만들기·학습·채점에서 지킬 것)

### 6-1. 자료 만들기
- **작은 사람 라벨은 확대해서 단다.** 선생 모델(가짜 라벨·미리 달기)을 돌릴 때 키가 작은 사람(약 120픽셀 미만)은 주변을 잘라 2~4배로 키워 돌리고, 관절을 원래 좌표로 되돌린다(자세 논문의 top-down 방식과 같은 생각). 원래 크기 결과와 확대 결과가 맞는 관절만 쓴다. 근거: LLVIP-Pose 시험에서 사람이 작을수록 관절이 정답 근처에 드는 비율이 크게 떨어졌다.
- **학습 그림은 원래 크기 그대로 둔다.** 장치는 640x480 원래 크기만 본다. 확대한 그림만 넣으면 원래 크기의 작은 사람을 못 찾는다. 크기 보강(±50%)과 부분 잘라 확대(1.4~4배)가 이미 확대·원래 크기를 섞어 보여 준다.
- **(11-15 고침, 7-6절)** 이 규칙이 코드에 빠져 있어 관절 2개 미만인 사람(**COCO 사람의 23%, 25,598명, 키 가운뎃값 36 px**; MOT17·LLVIP 0명, OTP2 14명)이 전체 상자로 학습됐다. 이제 학습·검증 변환에서 그 사람(과 몸 틀 맞추기에 실패한 사람)의 상자 안에 몸 상자를 정해진 비율로 놓는다: 윗변 +0.002 h, 높이 0.531 h, 가운데 -0.006 w, 너비 0.681 w. 비율은 관절이 잘 달린 COCO 사람 32,951명(보이는 관절 12개 이상)의 가운뎃값(높이 사분위 0.487~0.582). MOT17 은 키 50 px 미만부터 200 px 까지 0.505 로 일정해 작은 사람에게도 같은 비율을 쓴다. 코드 `scripts/pose_partial.py`(`BOX_ONLY`, `convert_box_only`), 학습 옵션 `--box-only-body 1`(0 = 11-15 이전과 같게), 시험 `scripts/test_box_only.py`, 측정 `scripts/measure_bodybox_ratio.py`, 결과 `results/bodybox_ratio_20261115.json`. 따로 다시 학습하지 않고 3단계 학습부터 적용한다(사용자: 원거리 판도 3단계 합친 모델로 곧 바뀜). **아주 작은 사람(키 약 40~50픽셀 미만)은 상자만.** 관절은 무시 표시(3), 상자는 몸 전체 상자를 정해진 비율로 머리~엉덩이 몸 상자로 바꿔 넣는다(비율은 MOT17 에서 잰다). 전신 상자를 그대로 넣으면 조준점이 허리 쪽으로 내려간다.
- **자료에 없는 관절 칸은 0 이 아니라 3.** 0 은 "안 보임"으로 학습되므로, 자료가 아예 라벨하지 않는 칸(LLVIP-Pose 의 눈·귀 등)은 3(무시)으로 둔다.
- **상자만 있는 사람(관절 0개)은 지우지 않는다.** 가림 보강이 이런 사람을 지우면 배경으로 배운다(`--keep-unlabelled 1`).
- **시험 녹화는 학습·가짜 라벨에 절대 쓰지 않는다.** 시험 세션과 같은 날·같은 세션 녹화도 뺀다(`tools/indoor_test_split.json`).
- **가짜 라벨 기준:** 상자 점수 0.5 이상 + 추적으로 6프레임 이상 이어진 사람만, 7프레임 이하 끊김은 머리·어깨·골반을 이어 채움(1), 관절은 점수 0.5 이상이고 좌우 뒤집기와 몸통 길이 5% 안에서 맞을 때만 2, 아니면 3. 중간 점수(0.3~0.5) 상자가 추적에 안 붙은 프레임은 버림. 100개를 사람이 봐서 90% 이상 맞아야 씀.
- **사람 없는 빈 배경을 넣는다 (11-15 결정, 3단계에서).** 원거리 판이 사람 없는 평평한 면(벽·천장)에서 높이 약 5000 px 가짜 사람 상자를 냈다(실카메라 첫 시험). 3단계 학습에 사람 없는 열화상 장면을 "사람 없음" 그림(라벨 빈 파일)으로 넣는다: 11-16 녹화의 처음·끝 빈 방, 평평한 면(벽·천장·바닥)을 비춘 장면, 우리 녹화에서 사람이 없는 구간. 오늘 따로 학습하지 않은 이유: 서버가 화면 높이 3배 넘는 상자를 버려 지금은 화면·짐벌에 나오지 않고, 내일 3단계와 따로 두 번 학습하면 검출기 출력에 맞춰 학습하는 모델(재인식 조각, 상자 다듬기, 위치 기억)도 두 번 다시 맞춰야 한다.
- **TMOT 컬러 짝으로 관절 옮기기는 하지 않는다.** 컬러와 열화상의 사람 번호가 서로 다르다(24편 중 21편). 컬러→열화상 옮기기는 픽셀로 맞춘 짝(LLVIP, KAIST, 우리 컬러 카메라)에서만.

### 6-2. 학습
- 조기 멈춤은 끈다. 다음 단계에는 last.pt 를 넘기고, 고르는 기준은 우리 실내 개발용 녹화와 원거리 시험(LLVIP-Pose 시험용)이다. Ultralytics 의 검증 점수는 몸 상자 점수가 섞여 흔들린다.
- 이미 다듬은 모델에서 다시 시작하면 학습률 1e-4, 짧게(6에폭 안팎), 2에폭마다 저장해서 고른다. 공개 자료로 오래 학습하면 우리 실내에서 나빠졌다(아래 7절).
- 한 번에 하나만 바꾼다. 비교는 같은 시작 가중치·같은 에폭·같은 설정, 다른 것은 시험하려는 하나뿐(대조 갈래).
- 26m 으로 방법을 정한 뒤, 필요할 때만 26x 를 같은 방법으로 한 번 학습해 가짜 라벨 선생으로 쓴다(장치에는 26m).
- **상자 떨림은 26m 이 아니라 별도 시간 모델로 잡는다 (11-15 결정).** 26m 은 그림 한 장씩만 보므로 앞뒤 프레임과 이어지게 학습할 수 없다(구조를 바꾸면 NPU 변환·속도·연속 라벨 문제). 같은 사람의 지난 프레임을 보는 작은 GRU "상자 다듬기"(과거 프레임만, 장치 CPU)를 우리 검출기 출력으로 학습하고 One Euro 필터와 비교한다(SmoothNet 같은 시간 보정 방식). 26m 이 3단계로 바뀌면 다듬기 모델과 위치 기억도 새 검출기 출력으로 다시 맞춘다.
- Vast 에서 학습은 한 번에 하나씩(메모리 부족으로 죽은 적 있음), 명령줄 기본값이 설정 파일을 덮어쓰는지 확인(FastTrackTr 는 에폭·저장 폴더가 덮어써졌음).

### 6-3. 채점
- 실내: 상자 하나 = 사람 하나. (a) 보이는 상자 중심이 예측 안이고 보이는 넓이 50% 이상이 예측 안, 또는 (b) 예측 상자 70% 이상이 보이는 상자 안이고 보이는 넓이 25% 이상을 덮음. (b) 가 없으면 가까이 있는 넓은 사람의 맞는 몸 상자가 놓침으로 셌다.
- 크기(보이는 키 <80, 80-160, 160-320, ≥320 픽셀)·보이는 정도·화면 가장자리별로 나눠 보고, 녹화 단위 부트스트랩 구간을 같이 본다. 개발용 녹화가 2개뿐이라 구간이 넓다.
- 최종 숫자는 공개 어려운 시험으로(3절), 최종 시험은 마지막에 한 번만.

### 7-3. FastTrackTr 열화상 학습 결과와 결정 (2026-11-15)

### 7-4. 단계별 수치와 의미 있는 차이인지 (2026-11-15 오전)
사람 자세 모델:
- 멀리 있는 작은 사람: 공개 열화상 자세 자료를 더하자 찾는 비율이 절반 수준에서 90% 넘게 올랐다(7,500명). **의미 있음**(다만 학습 자료와 같은 장소라 유리하게 나옴).
- 우리 실내 근거리: 장치에 있는 일찍 멈춘 모델이 두 녹화 **모두**에서 가장 좋았다(약 9점 차). 방향은 일관되지만 녹화가 2개뿐이라 **아직 확정 아님**. 11-16 새 녹화로 시험 세트를 늘려 판정한다.
- 많이 가려진 사람(공개 가림 시험): 모델 사이 1~2점, **차이 없음**(우연 범위).
- 공개 시험 점수는 오래 학습할수록 올랐지만(0.81 → 0.86) 우리 실내는 내려갔다: 공개 자료에 맞춰지는 현상.
- 가림 합성(사무실 책상·모니터) 학습: 진행 중, 대조 학습이 끝나면 같은 표에 넣는다.
엔드투엔드 추적 모델:
- 번호 손실 수정: 같은 사람 맞히기 30~50% → 85~95%. **의미 있음**.
- 열화상 학습: 공개 열화상 시험 6편 **모두** 좋아짐(평균 점수 약 15 → 27). **의미 있음**. 실내 두 녹화는 덜 찾음.
- 기존 방법(검출+추적기)보다는 아직 크게 낮음 → 학습 멈춤.
장치 속도: 엔드투엔드 한 장 53ms → 28ms (직접 측정).
우리 녹화 자동 라벨: 녹화 1개, 라벨 약 200개 → 부족, 11-16 새 녹화 필요.

### 7-5. 사무실 가림 합성 학습 결과 (2026-11-15 낮, 대조 학습은 진행 중)
R1 마지막 판에서 이어 6 epoch, lr 1e-4, 일찍 멈춤 없음, 2 epoch 마다 저장. 사무실 녹화에서 잘라 낸 책상·모니터·의자 조각 974개를 가림에 절반 섞고, 강한 가림(60~80%)을 갈수록 늘림. 대조 학습(C)은 조각 묶음만 빼고 같다.

| 모델 | 우리 실내 개발용 찾음 | 작은 사람(<80px) | 반 넘게 가려짐 | 헛상자/장 | LLVIP-Pose 찾음 | 작은 사람(<150px) |
| --- | --- | --- | --- | --- | --- | --- |
| E (장치 기본) | **51%** | 24% | 36% | 0.12 | 53% | 11% |
| R1 (원거리 선택지로 올림) | 42% | 13% | 24% | 0.12 | 93% | 77% |
| O 2 epoch | 42% | 16% | 24% | 0.07 | 94% | 75% |
| O 마지막(6 epoch) | 49% | 17% | 27% | 0.19 | **94%** | **79%** |
| C epoch2.pt (대조, 3 epoch 학습) | 48% | 13% | 25% | **0.07** | 94% | 78% |
| C 마지막(6 epoch, 대조) | 44% | 17% | 25% | 0.17 | 94% | 81% |

- O 마지막 판은 R1 보다 실내(+7점)와 원거리(+1~2점) **모두** 나음. 그래서 원거리 선택지는 O(또는 대조 C 가 더 나으면 C)로 바꾼다. 장치용 변환(관절 판 먼저)을 바로 시작했다.
- 장치 기본(E)과 비교하면 실내는 2점 낮고(녹화 2개, 90% 범위 [0.42, 0.66] 로 겹침, 차이 없음에 가까움) 원거리는 크게 나음. 헛상자는 한 사람 위에 상자가 하나 더 붙는 것(0.12 → 0.19). 가까운 사람 위 겹친 상자는 추적기가 대부분 흡수하지만, 기본을 바꾸려면 새 녹화(11-16) 시험 세트에서 다시 재야 한다.
- **대조(C) 결과와 결정 (11-15 13시):** 같은 학습 양끼리 보면 사무실 조각 묶음의 효과는 갈린다. 6 epoch 에서는 O 가 실내 4점 나음(49 대 44), 2 epoch 에서는 C 가 6점 나음(48 대 42). 녹화 2개라 **효과는 아직 판정 못 함**.
- MOT17 가림 시험(학습 안 쓴 2편, 몸 10~30% 보임 / 30~50%): R1 38.5 / 48.7, O 2 epoch 41.4 / 53.1, O 마지막 42.7 / 54.2, C 2 epoch 40.0 / 54.2, C 마지막 43.7 / 55.5. 이어 학습한 판 모두 R1 보다 2~6점 나음, 서로는 1~3점(우연 범위).
- **원거리 선택지는 C epoch2.pt 판(0부터 센 세 번째 epoch 끝 = 3 epoch 학습, 처음에 "2 epoch" 로 잘못 적음)으로 바꾼다.** 이유: O 마지막과 실내 찾음(48 대 49), 원거리(94 대 94, 작은 사람 78 대 79), 가림(40 대 43, 54 대 54)이 모두 우연 범위 안인데, 실내 헛상자(사람 위에 겹쳐 붙는 상자)가 0.07 대 0.19 로 3분의 1이다. 겹친 상자는 번호 바뀜과 짐벌 튐의 원인이 된다. 학습도 짧아(2 epoch) 앞 단계에서 덜 멀어졌다.
- 장치 기본(E)과 비교: 실내 찾음 48 대 51(우연 범위에 가까움), 헛상자 0.07 대 0.12(나음), 원거리 94 대 53(크게 나음), 반 넘게 가려진 사람 25 대 36(못함). 그래서 기본은 아직 E 그대로 두고 원거리 선택지로만 올린다. 기본을 바꿀지는 11-16 새 녹화로 늘린 시험 세트에서 판정한다.

### 7-6. 공개 어려운 시험 최종 표 (2026-11-15 저녁, 독립 검증 2회)
학습·선택에 안 쓴 부분만 채점. 관절 AP 는 OKS 0.50~0.95 평균(%). TMOT 상자는 계획 3절대로 예측 관절로 몸 전체 상자를 다시 만든 "관절 규칙". 검증자가 LLVIP-Pose(pycocotools)와 TMOT(공식 TrackEval)를 다시 계산해 숫자가 맞았다.

| 모델 | OTP2 시험용 관절 AP (학습 방식 / 논문 방식) | LLVIP-Pose 시험용 관절 AP (공식 13점) | TMOT 검증 HOTA / IDF1 | TMOT 키 25~50 px 찾음 |
| --- | --- | --- | --- | --- |
| E 장치 기본(근거리) | 80.4 / 86.0 | 45.9 | 19.5 / 18.4 | 7% |
| F 원거리 선택지(farc2) | 85.1 / 89.0 | 82.9 | **32.8 / 40.3** | 41% |
| R1 (참고) | 86.0 / 90.2 | 83.4 | 26.7 / 32.3 | 23% |
| O 가림 합성 (참고) | **86.8 / 90.9** | **84.2** | 32.7 / 40.2 | **43%** |
| P 학습 전 공개 모델 | 78.0 / 80.7 | 52.1 | 22.8 / 20.2 | 0% |

- **모든 상자 규칙에서 성립하는 것:** F·O 가 E 보다 낫다(TMOT HOTA +4~+16), P 가 E 보다 낫다(TMOT), F ≈ O. R1·O·F 사이 1~2점은 우연 범위. "F 가 P 보다 TMOT HOTA +10" 같은 크기는 관절 규칙에서만.
- **E 는 공개 시험 어디서도 이기지 못한다.** 기본 판으로 둔 근거는 우리 실내 근거리·가림 장면(7-5절)뿐이고, 공개 시험에는 그런 장면이 없다. 기본을 바꿀지는 11-16 새 녹화 시험 세트로 정한다(계획대로).
- **LLVIP-Pose 는 작은 사람 시험이 아니다**(사람 키 가운뎃값 = 모델 입력 132 px, 99.5% 가 COCO large). 밤 열화상 중거리이고, F·R1·O 는 같은 카메라 묶음으로 학습해 유리하다. 앞 절들에서 "원거리 93→94%"라고 쓴 숫자는 이 시험의 찾은 비율이다. **작은 사람은 TMOT 로 본다**(사람 68% 가 50 px 미만): F 41%, E 7%.
- 깨끗한 최종 시험(학습·선택 모두 안 씀)은 OTP2 시험용과 TMOT 검증뿐. LLVIP-Pose 와 MOT17-09/11 은 앞서 고르기에 썼다. MOT17 찾음 비율은 1:1 짝짓기가 아니라 내부 확인용(겹친 두 사람을 상자 하나로 찾은 걸로 셀 수 있음). TMOT 검증은 이제 상자 다듬기 학습의 검증에도 쓰므로 시스템 전체의 일회성 최종 시험은 아니다.
- **상자 모양이 크기에 따라 다르다(새로 찾음).** F·O 는 키 100 px 미만 사람에게 몸 전체 상자(발까지, 골반이 상자의 64~71%), 100 px 이상은 머리~골반(정답 키의 0.54). E 는 50~100 px 에서 0.65, R1 은 50 px 근처에서 바뀜. 원인: `pose_partial.to_body_boxes` 가 관절 2개 미만인 사람(주로 작은 COCO 상자만 사람)의 전체 상자를 그대로 두고, F·O 는 `keep_unlabelled` 로 그 사람들을 학습에 남겼다. 6-1절의 "아주 작은 사람은 정해진 비율로 몸 상자로" 규칙이 코드에 빠져 있었다. 영향: 장치에서 F 의 상자 높이·조준점(위에서 0.37)이 키 100 px 근처에서 약 2배 뛴다. 자동 선택은 문턱(100/140 px)이 그 뜀보다 위라 근거리로 잘못 바꾸지는 않는다. 고침(코드 반영됨, 6-1절): 3단계 학습부터 상자만 있는 사람을 잰 비율(COCO 0.531)로 몸 상자로 바꾼다. 상자 다듬기 모델도 한 가지 몸 상자 정의를 목표로 학습한다.
- 못 한 것: OCHuman(공식 양식에 개인 정보 입력 필요), KAIST(36 GB 전체 묶음뿐). KAIST 의 가림 정도별 놓침 질문은 아직 답하지 못했다.
- F 는 3 epoch 판(`epoch2.pt` 는 0부터 센 세 번째). 앞 절의 "C 2 epoch" 는 틀린 표기.
- 원본: 프로젝트 `close_range_20261113/final_eval_20261115/RESULTS_KO.md`.

### 7-2. 3단계 자기 학습 자료 시험 (2026-11-15)

- **하지만 쓸 수 있는 우리 실내 녹화가 하나뿐이었다.** 시험 녹화와 같은 날·세션을 빼고 나면 11-13 저녁 사무실 녹화 하나만 남아, 라벨 약 200개, 같은 사람 2~3명뿐.

## 8. 상황에 맞는 모델 자동 선택 (2026-11-15 사용자: "상황에 맞는 최적 모델을 알아서 고르게")
두 길을 같이 간다: (가) 근거리·원거리를 둘 다 잘하는 한 모델(3단계), (나) 그때까지 쓰는 자동 선택.
- **상황을 숫자로:** 거리(따라가는 사람, 없으면 화면 사람들의 몸 상자 키), 실내·실외(장면 온도 분포), 대비(사람과 배경 온도 차), 붐빔(사람 수·겹침), 카메라 움직임(짐벌 회전).
- **상황별 최적 모델은 측정으로 정한다:** 녹화를 재생해 후보 모델마다 상황별로 채점하고, 상황별로 가장 나은 모델을 표로 만든다. 새 모델을 올리면 같은 방식으로 다시 채점해 표를 고친다.
- **바꾸는 규칙:** 상황이 일정 시간 이어질 때만 바꾸고(예: 1초), 바꾼 뒤 최소 5초 유지, 들어가는 기준과 나오는 기준을 따로(왔다 갔다 방지). 모델 바꾸기에 검출이 약 0.5초 멈춘다.
- **녹화 재생 중에는 바꾸지 않는다**(재생이 처음부터 다시 시작됨). 대신 "여기서 바꿨을 것"만 기록하는 연습 모드로 기준값을 맞춘다.
- **같은 상자 모양끼리만 바꾼다:** 자세 모델은 머리~엉덩이 몸 상자, 예전 FLIR 모델은 보이는 전신 상자라서 짐벌 조준점이 다르다. 모양이 다른 모델 사이는 조준점 조정이 붙은 뒤에.
- **1차(만드는 중):** 거리 기준. 따라가는 사람 몸 상자 키가 100픽셀 아래로 1초 넘게 → 원거리 모델, 140픽셀 위로 1초 넘게 → 근거리 모델, 5초 유지, 사람이 없으면 3초 유지 뒤 10초에 기본으로. 근거: 우리 실내에서 지금 모델은 큰 사람(160픽셀 이상) 90% 넘게, 작은 사람은 20~30%만 찾고, 원거리 모델은 작은 사람을 70%대로 찾음. 값은 연습 모드 기록으로 맞춘다.
- **2차:** 실내·실외와 대비를 더하고, 상황별 최적 모델 표를 녹화 채점으로 만든다.
- **3차:** 남는 NPU 코어로 후보 모델을 가끔 같은 프레임에 돌려 지금 모델과 비교(검출 자신감, 추적이 이어지는 정도)하고, 여러 번 더 나으면 바꾼다. 표에 없는 상황도 고를 수 있게.
- **NPU 배치 (2026-11-15 사용자: 속도를 보고 배분 옵션을 정해 끊김 없이 바꿔도 됨):** (1) 지금: 한 모델을 코어 두 개에 번갈아, 바꿀 때 다시 올림(약 0.5초 멈춤). (2) 두 모델 상주: 근거리 코어 0, 원거리 코어 1, KeepID 코어 2, 프레임마다 고른 모델만 돌려 즉시 전환. (3) 경계 구간(예: 100~140픽셀)에서만 두 모델을 같은 프레임에 돌려 합침. 장치에서 옵션별 초당 프레임·지연·코어 사용률을 재서 기본을 정한다(2가 기본, 경계에서만 3 이 유력). 멈춤이 없어지면 최소 유지 시간을 줄일 수 있다.
- **결정 (사용자가 맡김, 11-15):** 기본은 (2) 두 모델 상주·즉시 전환, 경계 구간에서만 (3) 두 모델 함께. 이유: 전환 멈춤이 없고, 코어 3개 중 엔드투엔드·KeepID 와 겹치지 않게 배치 가능, 두 모델을 함께 돌리는 비용은 경계 구간에만 든다. 장치 측정에서 초당 프레임이 실시간(카메라 속도) 아래로 떨어지면 (3)을 빼고 (2)만.
- **고침 (사용자 11-15: 근거리·원거리가 정해지면 하나로 번갈아 돌리면 됨):** 정해진 동안은 그 모델 하나를 코어 0·1 에 번갈아(지금의 도착하는 대로 넣기와 같은 속도), 경계 구간에서만 코어 0 근거리 + 코어 1 원거리로 같은 프레임. 끊김이 없도록 두 모델을 두 코어에 모두 미리 올린다(엔진 4개). NPU 메모리가 모자라면 근거리는 두 코어, 원거리는 한 코어. 세 상태(근거리 번갈아 / 원거리 번갈아 / 경계 둘 다)마다 초당 프레임·지연을 잰다.
- **최신 연구 조사 반영 (11-15, 다섯 갈래 조사·원문 확인):** 사람 크기가 가장 싸고 잘 듣는 신호(TOD, ROMA, Remix). 잘 고른 고정 모델보다 몇 % 나은 정도지만, 고정 모델이 그 장면에 틀릴 때는 크게 이득(우리가 그 경우). 자주 바꾸는 시스템은 모두 모델을 미리 다 올려 둔다. 자신감만 보고 바꾸면 그 모델이 놓친 사람은 끝내 못 본다(SHIFT). 학습한 선택기·장면 분류는 이득이 작고, 확대·타일은 우리 시뮬레이션에서 손해, 실행 중 가중치 고치기는 INT8 NPU 에서 불가. 장기적으로는 한 모델(Pavlitska 2026: 전체 자료로 배운 한 모델이 나눠 배운 전문 모델들과 대개 같거나 나음).
- **그래서 1차 규칙을 고친다:** (가) 따라가던 사람을 잃거나 화면이 비면 바로 원거리 모델(근거리 모델은 작은 사람을 아예 못 봐서 작아지기를 기다리면 늦음). (나) 상자가 화면 끝에 닿았거나 보이는 관절이 적으면 "가려짐·잘림"으로 보고 원거리로 가지 않음(실내에서 상자가 작은 이유는 대개 거리가 아님). (다) 실패 비용이 달라 원거리 쪽으로 기움. 키는 약 1초 중앙값, 1분 전환 횟수 상한, 빠르게 움직일 때는 전환을 몇 초 미룸.
- **평가:** 항상 근거리 / 항상 원거리 / 정답을 아는 선택과 비교. 지표는 따라가는 사람을 놓친 프레임, 엉뚱한 사람에 붙은 비율, 다시 잡은 비율, 전환 횟수와 맞았는지. 실내 가림·실외 원거리·그 사이 장면. 값을 고르는 녹화와 평가 녹화를 따로.
- **2차:** 두 모델 상주 + 남는 코어로 가끔 확인 + 다시 보기 채점으로 만든 키 구간·실내외별 표(정답 라벨로 찾는 비율과 헛상자). 조사 원문: 프로젝트 close_range_20261113/research_model_selection_20261115/.
- 화면 "검출 모델 자동 선택" 줄, 기본 꺼짐.

- **실카메라 첫 시험에서 고친 것 (11-15 14시, 장치 재부팅 뒤 카메라가 돌아옴):** 카메라가 평평한 면(사람 없음)을 보는 동안 원거리 판이 높이 약 5000 px, 점수 0.46 짜리 가짜 사람 상자를 냈다(근거리 판은 아무것도 안 냄). 자동 선택은 이것을 "잘린 큰 사람"으로 읽어 근거리로 바꾸고, 근거리 판이 아무도 못 보니 3초 뒤 먼 거리로 되돌아가 30초에 5번 오갔다. 고침: (1) 높이 1440 px(화면 높이 3배, 0.3 m 보다 가까운 사람에서나 가능)보다 큰 상자는 크기 신호에서 뺀다.
