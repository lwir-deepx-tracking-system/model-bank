## NPU에 올리려고 바꾼 구조 (`ftt_npu_variant.py`의 `FullNPU`)

DX-M1 NPU에 TopK / GridSample / Log가 없어서 아래처럼 바꿨습니다. 학습도 이 구조로 해야 합니다.

1. 질의 300개 = 가장 작은 층의 15×20칸 그대로 (TopK 없음)
2. 디코더 교차 어텐션 = 일반 다중 헤드 어텐션 (변형 샘플링 없음). 키는 가장 작은 층 300칸(`FTT_KV_FROM=2`)
3. 상자 보정은 로그 없이 펴지 않은 값을 누적
4. 앞 장 출력(`traj`)은 입력으로 받고, 첫 장에는 0 (0/1 스위치 입력은 컴파일 실패)
5. 디코더 층 수 줄이기 가능 (`FTT_DEC_LAYERS=2`)

## 컴파일러(DX-COM 2.4.1) 제약

- 디코더 층을 한 그래프에 3개 이어 붙이면 CODEGEN에서 실패. 실제 모델은 2층 묶음도 실패 → **층마다 그래프 하나**
- 인코더 출력을 토큰으로 펴는 부분이 CPU 조각으로 빠지면 호출마다 약 35ms 손해 → **AE 그래프**(앞부분 + 인코더 + 인코더 출력 계산)를 4차원(NHWC)으로 두어 NPU만으로 컴파일, 호스트는 모양만 바꿈
- 입력이 여러 개인 그래프의 보정 데이터는 입력 이름별 사전으로 (튜플이면 보정 단계 실패)

## 장치 측정 (ResNet-18 판, 무작위 가중치, 서버 검출기가 코어 0에서 도는 중)

| 구성 | 시간 |
| --- | --- |
| CPU만 (공식 구조) | 1.1~1.25초/장 |
| NPU, 키 1,500개, 디코더 3층 | 105ms/장 |
| NPU, 키 300개, 디코더 3층 | 61ms/장 |
| **NPU, AE + 디코더 2층(키 300)** | **47ms/장 = 21fps, 파이프라인 34.6fps** |

- AE 20ms(코어 1), 디코더 2층 28ms(코어 2). 앞부분을 코어 두 개로 나눠도 34.7fps로 같음 → 병목은 디코더
- 한 엔진에 여러 코어를 묶는 옵션(NPU_01, NPU_12, NPU_ALL)은 이 모델에서 런타임이 거부. 코어마다 엔진을 따로 두는 방식은 됨

## 파일

- `ftt_npu_variant.py` — NPU용 구조, ONNX 내보내기(전체 / A / AE / 디코더 조각), DX-COM 컴파일
- `ftt_full_pipeline3.py` — 장치에서 AE + 디코더 조각 시간 측정 (차례로, 파이프라인, 30fps 맞춤)
- `ftt_bisect.py` — 디코더 블록별 컴파일 시험(어디서 실패하는지)
- `ftt_call_cost.py` — 한 번 호출의 NPU 계산 대 나머지 시간
- `dxnn_cpu_ops.py` — .dxnn 안 CPU 조각의 연산 목록
- `ftt_profile.py` — 공식 구조를 CPU로 돌린 부분별 시간
- `ftt_a_multi.py` — 코어마다 엔진을 따로 두고 번갈아 넣는 시험
