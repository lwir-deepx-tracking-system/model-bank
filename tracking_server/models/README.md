# 모델 파일 (`tracking_server/models/`)

추적 서버가 쓰는 모델 파일이 일별 폴더에 들어 있습니다.

- **[`detect/`](detect/)** — 검출 모델. 구조별 폴더 `yolo26m/` `yolo26s/` `yolo26x/` `yolov8/` `yolox/` 와 만든 스크립트 `build_scripts/`. 자세한 글: 이 글 1절.
- **[`track/`](track/)** — 추적에 쓰는 작은 모델: 확인 판정기, 번호 잇기 판정기, 위치 기억. 자세한 글: 이 글 2절, [track/README.md](track/README.md).
- **[`reid/`](reid/)** — 외형 비교(re-ID) 모델. 자세한 글: 이 글 3절, [reid/README.md](reid/README.md).
- **[`MANIFEST.json`](MANIFEST.json)** — 모델 파일 확인값(sha256)과 `내부 이름 -> 파일` 표. 자세한 글: 이 글 4절.

읽는 법:

- 입력·출력 모양은 **모델 파일 안에 적힌 값**을 2026-11-11 에 읽은 것입니다. DXNN 은 모두 INT8 이고 입력은 uint8 NHWC `[1,높이,너비,3]`(8비트 흑백을 3채널로 복제, 정규화 없음), 출력은 float32 입니다.
- "보정"은 INT8 로 바꿀 때 쓴 그림 수입니다(파일 안의 값, 방식은 모두 EMA).
- 측정값에는 날짜와 조건을 붙였습니다. 따로 적지 않은 것은 **한 번 잰 값**이고 구간 추정을 하지 않았습니다.
- 지난 측정표 전체와 지운 모델의 기록은 git 기록의 옛 README 에 있습니다.

## 1. 검출 (`detect/`)

"분할 출력 6개"는 `box_s8` `box_s16` `box_s32`(채널 4) 와 `cls_s8` `cls_s16` `cls_s32`(채널 16) 입니다. 640×480 입력이면 격자가 60×80, 30×40, 15×20 이고 640×640 입력이면 80×80, 40×40, 20×20 입니다. 상자 풀기·시그모이드·NMS 는 서버(`src/detect/`)가 합니다.

출력이 하나인 모델은 세 가지를 받습니다. N 은 앵커 수입니다(640×640 입력 8,400, 640×480 입력 6,300).

- `[1,300,6]` — NMS 까지 끝난 상자 목록. 서버는 그대로 씁니다 (이름에 `[NMS-free]`).
- `[1,20,N]` (YOLOv8 꼴) — 앵커마다 `cx,cy,w,h`(입력 픽셀) 4줄 + 클래스 점수 16줄(0~1).
- `[1,N,21]` (YOLOX 꼴) — 앵커마다 `cx,cy,w,h`(입력 픽셀) + 물체 점수 1 + 클래스 점수 16(0~1). 서버가 물체 점수 × 클래스 점수를 점수로 씁니다.

뒤의 두 꼴은 상자가 파일 안에서 이미 풀려 나옵니다. 서버는 분할 출력 모델과 **같은 NMS** 만 합니다(점수 0.001 초과, 클래스별, IoU 0.7 초과면 지움, 최대 300개).

### 재지 않은 것

- **실내 fine-tuning 두 판과 실외 fine-tuning patch 판: 장치 INT8 정확도를 재지 않았습니다.** 위 값은 PC 에서 잰 것입니다.
- 실외 fine-tuning patch 판: FLIR 검증을 하지 않았습니다. 실외 실시간 시험으로 쓸지 정합니다.
- YOLO26s 640x480: 장치 정확도를 재지 않았습니다. YOLO26m_(FLIR) 640x480 은 위 2026-11-06 파일 실행 한 번이 전부입니다.
- 실내 fine-tuning 판은 실외와 FLIR 영상에 쓰지 않습니다(옛 README 와 이름표의 주의).
- **YOLOv8n·YOLOv8s·YOLOX-nano·YOLOX-s 네 파일: 장치에서 한 번도 돌려 보지 않았습니다.** 정확도, 속도, 오검출 모두 잰 값이 없습니다. 쓰기 전에 아래 "YOLOv8·YOLOX 를 장치에서 처음 켤 때 볼 것"을 확인합니다.

### YOLOv8·YOLOX 를 장치에서 처음 켤 때 볼 것

출력의 뜻은 2026-11-13 에 파일 안의 CPU 부분(ONNX)을 꺼내 PC 에서 돌려 확인했습니다(같은 식을 numpy 로 계산한 값과 차이 0.00002 이하). NPU 부분은 PC 에서 돌릴 수 없어서 아래는 확인하지 못했습니다.

1. 목록에 나오는지: 서버를 다시 켠 뒤 화면의 YOLOv8, YOLOX 폴더에 두 개씩 보여야 합니다. 안 보이면 서버 로그의 `BANK file not listed:` 줄에 이유가 있습니다.
2. 바꿔지는지: 고르면 그 모델로 바뀌어야 합니다. "실패해서 이전 모델로 되돌림"이 나오면 장치가 알려 주는 출력 모양이 파일에 적힌 것과 다른 것입니다.
3. 사람 상자: 사람이 또렷이 보이는 장면에서 상자가 사람에 맞고, 점수가 보통 수준(대략 0.3 이상)이고, 종류가 사람이어야 합니다. 점수가 모두 0 근처이거나 상자가 화면을 뒤덮으면 입력 밝기 처리(YOLOv8 은 255 로 나누기, YOLOX 는 나누지 않음)나 클래스 순서가 가정과 다른 것입니다.
4. 오래 켜 두기: YOLOX 는 몇 백 프레임을 돌려 서버가 멈추지 않는지 봅니다(출력에 숫자가 아닌 값이 나오면 서버는 멈춥니다. 다른 모델과 같은 규칙).
5. 그 다음에 정확도·속도·오검출을 다른 모델과 같은 방법으로 잽니다. 재기 전에는 권하지 않습니다.

알아 둘 것:

- YOLOX 의 NMS 도 서버의 한 가지 규칙(클래스별, IoU 0.7)을 씁니다. YOLOX 원래 설정(0.45~0.65)보다 겹친 상자가 조금 더 남을 수 있습니다.
- 보정 그림: 옆의 `_compile_metadata.json` 에는 보정 폴더가 `<YOUR_PATH>` 로 가려져 있지만, 네 `.dxnn` 파일 안에는 폴더 이름이 남아 있습니다. 모두 `calibration_train_only` 로 끝나고, YOLOX 두 파일은 그 위 폴더가 `yolox_nano_canonical_canvas_dxnn_20261020_v2`, `yolox_s_canonical_canvas_dxnn_20261020_v2` 입니다. 보정 그림 100장과 그림을 640×640 에 놓은 방법은 저장소에 없습니다.
- 그림 놓는 자리(확인 못 함): 서버는 640×640 모델에 카메라 그림을 가운데(80~560줄)에 놓고 위아래를 밝기 114 로 채웁니다. YOLOX 원래 방식은 그림을 위에 붙이고 아래만 채웁니다. 학습·보정 때 어느 쪽이었는지 모릅니다. 달라도 상자 자리는 맞게 나오지만(서버가 자기가 놓은 자리로 되돌림) 정확도가 낮아질 수 있습니다. 5번에서 정확도가 이상하게 낮으면 이것부터 봅니다.
- PC 시험(NPU 없이, 지어낸 출력으로 상자·점수·종류와 좌표를 확인): `cd tracking_server && python3 -m unittest src.detect.test_model_kinds`

### 화면 목록에 나오지 않는 파일

- **YOLO26x PyTorch 체크포인트 (DXNN 아님, Git LFS)**
  - 파일 `yolo26x/yolo26x.pt`
  - 입력: 학습 640×640, 평가 480×640. 출력 —
  - 학습: FLIR 학습 10,491장, 30 epoch. 보정 —
  - 메모: 라벨 후보를 만드는 데 쓰는 모델. PC 평가 사람 AP50:95 53.28 %, AP50 84.56 % (FLIR 검증 1,144장). 장치용으로 바꾸거나 돌려 보지 않음.
  - 학습 설정은 `yolo26x/yolo26x_train_metadata.json`

각 DXNN 옆의 `*_compile_metadata.json` 은 그 파일 안의 컴파일 기록을 꺼낸 것입니다(실행에는 필요 없음). `build_scripts/` 에는 640×480, 640×640, NMS 없는 모델을 만든 스크립트가 있습니다.

## 2. 추적 (`track/`)

DXNN 이 아니라 가중치가 든 JSON / npz 이고, 서버가 장치 CPU 에서 numpy 로 계산합니다. 입력 특징의 뜻은 [track/README.md](track/README.md)에 있습니다.

각 항목: 화면 이름 — 파일, 입력, 출력, 학습 자료, 측정값, 상태 · 재지 않은 것.

- **(화면에 없음) 확인 판정기**
  - 파일 `track/gate_gru32_frozen.json`
  - 입력 `[N,11,19]` = 추적 N개 × 11프레임 × 특징 19개
  - 출력 `[N]` 0~1, 0.3 이상이면 새 번호를 내보냄
  - 학습: TMOT 학습 24편
  - 측정: 프레임당 평균 0.18 ms (옛 README 기록, 장치 CPU)
  - 상태: 켜기 스크립트가 `--confirm-gate` 로 넘김. **실시간 서버에서는 쓰이지 않고** 파일 실행에서만 쓰임(실시간은 화면에서 고른 추적기를 씀)
- **(화면에 없음)**
  - 파일 `track/gate_gru32_inside_20261110.json`
  - 입력: 위와 같음. 출력: 위와 같음, 기준 0.35
  - 학습: 위 판정기에서 시작한 fine-tuning. 파일 이름은 실내(inside) 이고 파일 안에 자료 설명은 없음
  - 측정: 검증 1회: 틀린 확인 1 / 맞는 확인 83 (위 판정기 5 / 70)
  - 상태: 후보. 서버가 쓰지 않음. 장치에서 재지 않음
- **(화면에 없음)**
  - 파일 `track/gate_gru32_office_20261110.json`
  - 입력: 위와 같음. 출력: 위와 같음, 기준 0.3
  - 학습: 위 판정기에서 시작한 fine-tuning. 파일 이름은 사무실(office) 이고 파일 안에 자료 설명은 없음
  - 측정: 파일에 없음
  - 상태: 후보. 서버가 쓰지 않음. 장치에서 재지 않음
- **(화면에 없음) 번호 잇기 판정기**
  - 파일 `track/relink_judge_frozen.json`
  - 입력: 새 번호와 사라진 번호 한 쌍의 특징
  - 출력: 같은 사람일 점수
  - 학습: TMOT 검증 6편의 정답 쌍 1,430개
  - 측정: TMOT 검증 교차 확인: IDF1 0.692, 되돌린 58건 중 같은 사람 39 / 다른 사람 11 / 모름 8 (파일 안의 기록)
  - 상태: 켜기 스크립트가 `--judge` 로 넘김. RepVGG_distillation_(TMOT,CAMEL)_20261103 의 점수로 맞춘 것이라 다른 외형 모델과는 확인되지 않음
- **GRU 위치 기억**
  - 파일 `track/pos_gru.json`, `pos_gru.npz`
  - 입력: 놓친 사람 한 명, 프레임마다 숫자 16개
  - 출력: 숫자 4개 (Kalman 예측 상자를 고치는 값)
  - 학습: 1 epoch 만 학습한 시험용 가중치
  - 측정: 없음
  - 상태: **쓰지 마세요**(화면에도 그렇게 나옴). 확인하지 않음
- **Mamba 위치 기억**
  - 파일 `track/pos_mamba.json`, `pos_mamba.npz`
  - 입력: 위와 같음. 출력: 위와 같음
  - 학습: 1 epoch 만 학습한 시험용 가중치
  - 측정: 없음
  - 상태: **쓰지 마세요**(화면에도 그렇게 나옴). 확인하지 않음

화면의 위치 기억 기본값은 학습 모델이 없는 "Kalman filter + 카메라 움직임 보정"입니다.

## 3. 외형 비교 (`reid/`)

다섯 파일 모두 입력 `images` `[1,128,64,3]`(높이 128, 너비 64), 출력 `embedding` `[1,128]`, 보정 256장입니다. 모양이 같아서 서버를 켠 채로 화면에서 바꿀 수 있습니다. 사람 조각을 만드는 법은 [reid/README.md](reid/README.md)에 있습니다.

각 항목: 화면 이름 — 파일, 학습 자료, 측정값, 상태 · 재지 않은 것.

- **RepVGG_distillation_(TMOT,CAMEL)_20261103**
  - 파일 `reid/repvgg_tmot_camel_reid.dxnn`
  - 학습: teacher SOLIDER 에서 distillation. TMOT 학습 24편 + CAMEL 14편 + FLIR 사람 조각
  - 측정: 조각 한 장 NPU 코어 2 에서 2.3 ms (옛 README 기록)
  - 상태: 켜기 스크립트의 시작 모델 (`--relabel RVGGA0_REID2C256`). TMOT·CAMEL 로 학습했으므로 그 영상에서 잰 값은 상한값
- **RepVGG_distillation_(실내)_20261110**
  - 파일 `reid/repvgg_distill_inside_20261110_reid.dxnn`
  - 학습: teacher SOLIDER, 우리 카메라 실내
  - 측정: 없음
  - 상태: 시험용. **장치 INT8 정확도 미측정**
- **RepVGG_fine-tuning_(실내)_20261110**
  - 파일 `reid/repvgg_ft_inside_20261110_reid.dxnn`
  - 학습: 우리 카메라 실내
  - 측정: 없음
  - 상태: 시험용. **장치 INT8 정확도 미측정**
- **ViT-lite_distillation_(실내)_20261111**
  - 파일 `reid/vit_lite_distill_inside_20261111_reid.dxnn`
  - 학습: teacher SOLIDER, 우리 카메라 실내
  - 측정: 없음
  - 상태: 시험용. **장치 INT8 정확도 미측정**. 마지막 단계만 파일 안의 CPU 부분
- **ViT-lite_fine-tuning_(실내)_20261111**
  - 파일 `reid/vit_lite_ft_inside_20261111_reid.dxnn`
  - 학습: 우리 카메라 실내
  - 측정: 없음
  - 상태: 시험용. **장치 INT8 정확도 미측정**. 마지막 단계만 파일 안의 CPU 부분
- **RepVGG_fine-tuning_(OTP2)_20261113**
  - 파일 `reid/repvgg_ft_otp2_20261113_reid.dxnn` (내부 이름 `REPVGG_FT_OTP2_20261113`)
  - 근거리 몸 네모 검출 모델(`yolo26m_pose_otp2_20261113_bodybox_640x480`)과 함께 쓰는 외형 모델. 조각이 몸 네모(머리~골반)를 화면 안으로 자른 것이라, 화면 가장자리에서 잘리고 늘어난 조각과 물체에 가려진 조각으로 학습했습니다.
  - 학습: RepVGG_distillation_(TMOT,CAMEL)_20261103 에서 시작. OpenThermalPose2 실내 앉은 사람 부분의 실제 신원(사람+회차, 학습 200신원 3,563장)으로 batch-hard triplet, 원래 공개 조각에서는 원래 모델 값 유지(약하게). 3000 step.
  - PC 측정(INT8 아님): OpenThermalPose2 시험 60신원 1순위 정답 비율 몸 네모 72→89%, 잘림 18→27%, 가림 65→84%. 우리 실내 녹화 점수 몸 네모 0.79→0.81(검증)·0.92→0.92(시험), 잘림 0.72→0.75·0.78→0.87, 가림 0.75→0.79·0.88→0.84, 몸 전체 조각 0.81→0.79·0.95→0.93.
  - 몸 전체 조각에서는 조금 나빠지므로 예전 검출 모델과는 쓰지 않습니다. 번호 잇기 판정기는 원래 모델 점수로 맞춘 것이라 이 모델과의 결과는 확인되지 않았습니다. 시험용, 장치 INT8 정확도 미측정.


실내 모델 네 개의 학습 장 수와 PC 평가 값은 이 저장소에 기록이 없습니다.

## 4. 서버가 모델을 찾는 법

1. `scripts/setup.sh` 가 `MANIFEST.json` 의 `_links` 표대로 `models/links/<내부 이름>.dxnn` 링크를 만들고(이 폴더는 git 에 올리지 않음), 내부 이름 9개와 `_files` 의 DXNN 18개를 sha256 으로 확인합니다. 하나라도 다르면 멈춥니다.
2. 서버는 내부 이름이 있는 모델(검출 4개, 외형 5개)을 `models/links/` 에서 찾고, 올릴 때 `MANIFEST.json` 의 값과 다시 대조합니다.
3. 내부 이름이 없는 검출 모델은 서버가 `models/detect/` 와 그 바로 아래 폴더를 훑어 스스로 찾습니다. 파일 안의 입력이 640×480 또는 640×640 uint8 이고 출력이 분할 출력 6개이거나, 하나이면서 `[1,300,6]` · `[1,20,N]` · `[1,N,21]` 가운데 하나일 때만 목록에 올립니다(1절, 클래스 16개). 그 밖의 파일은 올리지 않고 서버 로그에 `BANK file not listed:` 와 이유를 남깁니다. 그래서 **새 검출 모델은 `models/detect/<구조>/` 에 파일을 넣기만 하면** 목록에 나옵니다(옆에 `display_name` 이 든 `<파일 이름>.json` 을 두면 그 이름으로).
4. 새 외형 모델은 파일을 넣는 것만으로는 나오지 않습니다. `MANIFEST.json` 에 내부 이름·확인값·`_links` 를 적고 `src/reid/reid_models.py` 의 목록에 이름을 더해야 합니다.

모델 파일 이름은 바꾸지 마세요. `MANIFEST.json` 과 이름표가 그 이름을 씁니다.
