# 추적에 쓰는 작은 모델 (`models/track/`)

파일 목록·학습 자료·상태는 [../README.md](../README.md) 2절에 있습니다. 여기는 확인 판정기(`gate_gru32_*.json`)가 무엇을 받고 무엇을 내는지 적은 글입니다. 값은 JSON 파일과 코드 `src/track/gate.py` 에서 옮겼고, 장치에서 다시 재지는 않았습니다.

## 확인 판정기 (`gate_gru32_frozen.json`)

DXNN 이 아니라 가중치가 든 JSON 이고, 서버가 numpy 로 직접 계산합니다(NPU 를 쓰지 않음).

| 항목 | 값 |
| --- | --- |
| 하는 일 | 새로 생긴 사람 추적을 화면에 내보낼지 정합니다. 이미 내보낸 추적은 건드리지 않습니다 |
| 입력 | `[N, 11, 19]` float. N = 이번 프레임에 판정할 추적 수, 11 = 지난 10프레임 + 지금 프레임(오래된 것이 앞), 19 = 프레임당 특징 수 |
| 기록이 짧을 때 | 앞쪽을 0 으로 채웁니다. 이때 19번째 특징 `valid` 도 0 입니다 |
| 출력 | `[N]` float, 0~1. 그 추적이 진짜 사람일 확률. `thr_out`(0.3) 이상이면 내보냅니다 |
| 구조 | GRU 1층(은닉 32) → 마지막 은닉 상태 → 선형 1개 → sigmoid |
| JSON 키 | `hidden` 32, `n_features` 19, `window` 11, `thr_out`, `thr_low`, `weights` |
| 쓰이는 곳 | `--confirm-gate` 를 준 **파일 실행**. 실시간 서버는 화면에서 고른 추적기를 씁니다 |

`gate_gru32_inside_20261110.json`, `gate_gru32_office_20261110.json` 은 같은 입력·출력에 "다음 상자" 출력(`next_head`)이 더 들어 있는 후보 파일이고, 서버는 쓰지 않습니다.

## 프레임당 특징 19개 (이 순서 그대로)

상자 좌표는 640×512 캔버스 기준입니다(640×480 영상은 위쪽 16 px 아래에 놓입니다). h = 상자 높이, w = 상자 너비.

| 번호 | 이름 | 값 |
| --- | --- | --- |
| 1 | matched | 이번 프레임에 검출과 짝이 맞으면 1, 아니면 0 |
| 2 | matched_low | 낮은 점수 검출과 짝이 맞으면 1 |
| 3 | conf | 짝이 맞은 검출의 신뢰도 |
| 4 | h | h / 480 |
| 5 | aspect | w / h |
| 6 | logh | ln(h) |
| 7 | speed | 직전 프레임에서 중심이 움직인 거리 / h (최대 5) |
| 8 | kf_iou | Kalman 예측 상자와 검출 상자의 IoU |
| 9 | overlap | 다른 사람 추적 상자와의 최대 IoU |
| 10 | contrast | (상자 안 평균 − 상자 둘레 띠 평균) / (띠 표준편차 + 1), −8~8 |
| 11 | texture | 상자 안 표준편차 / 64 (최대 4) |
| 12 | hits | 짝이 맞은 횟수(최대 30) / 10 |
| 13 | misses | 놓친 횟수(최대 30) / 10 |
| 14 | cmiss | 연속으로 놓친 횟수(최대 30) / 10 |
| 15 | age | 생긴 뒤 프레임 수(최대 60) / 30 |
| 16 | edge | 영상 가장자리까지 가장 가까운 거리 / h, −1~2 |
| 17 | lost_iou | 놓친 사람 추적의 예측 상자와의 최대 IoU |
| 18 | lost_dist | 놓친 사람 추적 중심까지 가장 가까운 거리 / h (최대 5, 없으면 5) |
| 19 | valid | 실제 기록이면 1, 채운 칸이면 0 |

특징의 순서·개수(19)와 창 길이(11)는 코드와 JSON 이 같아야 합니다.
