# NPU 온도와 프레임 주기 지키기 (2026-11-16)

## 한눈에
- 실시간 서버가 도는 동안 DX-M1 NPU 온도가 88~93°C 까지 올라가고, 칩이 스스로 클럭을 1000 → 800 → 600 MHz 로 낮췄다가 올리기를 몇 분 간격으로 되풀이했습니다(`dxrt-cli -s`).
- 원인: 보드의 팬은 **본체(CPU) 온도만** 보고 돕니다. 본체는 50~57°C 라 팬이 20~39% 로만 돌고, NPU 모듈이 뜨거워도 빨라지지 않습니다.
- 대응 두 가지: (1) NPU 온도를 보는 가변 팬 `scripts/npu_fan.sh`, (2) 검출이 느려지면 NPU 코어 0·1 교대로 스스로 바꾸는 투입 방식(만드는 중, 아래 4절).

## 1. 잰 값 (장치, 2026-11-15 밤 ~ 11-16)
| 상태 | NPU 0 / 1 / 2 | 클럭 | 본체 | 팬(255 중) |
|---|---|---|---|---|
| 실시간 서버 동작(범용 26m 검출 + 외형 모델) | 89~90 / 90~92 / 91~93°C | 600~1000 MHz 를 오감 | 54~58°C | 100 |
| 화면 출력이 약 2분 멈춘 동안 | 90 → 63°C 로 내려감 | 1000 MHz | 49~52°C | 50~150 |
| 검출이 다시 돌기 시작한 뒤 2분 | 63 → 88°C | 1000 MHz | 51~54°C | 255 와 50 을 오감(아래 3절) |

- 세 코어가 거의 같은 온도입니다. 검출이 거의 안 가는 코어 1 도 같이 뜨겁습니다(한 칩).
- 쉬면 2분 안에 25°C 넘게 식습니다. 열은 검출이 계속 돌 때 생기는 열입니다.
- 평소 온도 기록은 없었습니다. 이 날부터 장치에 1분마다 기록을 남겼습니다(온도·클럭·팬 값, 12시간).

## 2. 공개된 온도 범위 (DX-M1 M.2 모듈)
- 제 속도로 동작: −25 ~ 65°C. 속도를 낮추며 동작(스로틀링): 85°C 까지. 판매처 자료(Digi-Key, Avnet, DFRobot)에 같은 값이 있습니다.
- 이 값이 주변 온도 기준인지 칩 온도 기준인지는 자료에 없습니다. 칩이 클럭을 낮추기 시작하는 정확한 온도도 확인하지 못했습니다(잰 것으로는 90°C 안팎에서 낮춤).
- 모듈용 방열판이 따로 팔립니다.

## 3. 팬
- 보드 팬 드라이버(pwm-fan, `rockchip,temp-trips`)는 본체 온도 50 / 55 / 60 / 65 / 70°C 에서 팬 값을 50 / 100 / 150 / 200 / 255 로 올립니다. NPU 모듈 온도는 보지 않습니다.
- 손으로 `pwm1` 에 255 를 써도 드라이버가 1초 안에 자기 값으로 되돌립니다.
- `scripts/npu_fan.sh`: 5초마다 가장 뜨거운 NPU 코어 온도를 읽어 팬 값을 정하고, 드라이버가 되돌리는 것을 이기도록 0.1초마다 다시 씁니다. 본체가 정한 값보다 낮추지는 않습니다.

| NPU 온도 | 팬 값 |
|---|---|
| 65°C 미만 | 보드가 정한 대로 |
| 65°C 이상 | 150 |
| 72°C 이상 | 200 |
| 78°C 이상 | 255 |
| 60°C 이하로 내려가면 | 다시 보드에 맡김 |

- 설치: `scripts/npu-fan.service.example` 을 `/etc/systemd/system/npu-fan.service` 로 복사하고 `ExecStart` 경로를 맞춘 뒤 `sudo systemctl daemon-reload && sudo systemctl enable --now npu-fan`. 끄기: `sudo systemctl disable --now npu-fan`.
- **아직 확인 못 한 것:** 처음 판(1초마다 다시 씀)은 팬이 255 와 50 을 오가서 절반만 돌았고, 그 상태에서는 검출이 돌면 88°C 까지 다시 올랐습니다. 0.1초 판으로 팬이 최대로 유지될 때 몇 도에서 멈추는지는 아직 재지 않았습니다. 팬 최대로도 80°C 아래로 안 내려가면 모듈에 방열판을 붙여야 합니다.

## 4. 느려질 때 프레임 주기 지키기
- 검출 투입 방식은 둘입니다(`src/detect/frame_feed.py`, `LATENCY.md`): 단독(NPU 0 만, 지연 약 48~50 ms)과 교대(NPU 0·1 번갈아, 약 57 ms).
- 26m 검출은 한 장 25 ms 라 코어 하나로 카메라 주기(33 ms, 초당 30장)를 따라갑니다. 클럭이 600 MHz 로 내려가면 한 장이 33 ms 를 넘을 수 있고(클럭 비율로 어림 약 40 ms, 잰 값 아님), 그러면 단독으로는 프레임이 버려집니다.
- 교대는 **장수를 지키는 보험**입니다. 느려져도 초당 30장은 유지하지만, 각 장이 늦게 나오는 것은 그대로이고 평소 지연을 7~9 ms 더 냅니다.
- 계획(만드는 중): 평소에는 단독, 검출 처리 시간이 카메라 주기를 못 지키면 스스로 교대로, 회복되면 다시 단독으로. 가장 새 프레임만 처리하고, 주기를 못 지킨 횟수·버린 프레임·전환 횟수와 이유를 `/rules` 에 표시. 끝나면 이 절과 `LATENCY.md` 에 숫자를 적습니다.
- NPU 코어 쓰임(11-16 확인): 코어 0 검출, 코어 1 교대일 때 검출(단독일 때 거의 쉼), 코어 2 외형 모델·번호 잇기 판정.

## 5. 다음
- 0.1초 판 팬으로 온도가 어디서 멈추는지, 클럭이 1000 MHz 로 유지되는지 기록으로 확인.
- 안 되면 방열판. 그동안 지연 측정값은 클럭이 1000 MHz 인지 같이 적어야 비교할 수 있습니다.
