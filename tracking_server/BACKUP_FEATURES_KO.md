# 운영 백업 기능 통합

2026-11-20 운영 백업의 추가 기능을 현재 main에 옮겼습니다. 백업 전체를 덮어쓰지 않았습니다. Space 홈, 실제 각도 눈금, JPEG 전송, 최근 3장 0 ms 시간표, OC-SORT와 결과 저장 경로를 유지합니다. 웹 JPEG→H264 프록시·빨간 정지 버튼·제거한 안내 문구는 복원하지 않습니다. 모델 가중치와 현장 영상·라벨은 추가하지 않습니다.

## 한 장 분할 · NPU 0·1

같은 프레임을 겹치는 좌우 두 타일로 나누고 NPU 0·1에 제출한 뒤 합칩니다. 프레임을 번갈아 두 코어에 보내는 교대 모드와 다릅니다.

지원하는 관절 모델은 기존 E10, LWIR1056 E10, LWIR650 E10, LWIR650 temporal E13입니다. 각 모델에 맞는 분할 DXNN과 원본 DXNN의 SHA256을 확인합니다. 분할 파일은 `models/optimized/`에 별도로 있어야 합니다. 지원 모델을 바꿀 때 이전 분할 실행기를 해제하고 새로 준비합니다. 준비 실패 시 옵션을 잠그고 사유를 보고합니다. 선택한 모델이 다른 경우 분할 모델을 대신 사용하지 않습니다.

GUI의 System에서 **한 장 분할 · NPU 0·1 동시 검출**을 선택하고 적용합니다. `GET /rules`의 `npu_feed.tile_available`은 사용 가능 여부, `tile_active`는 실제 활성 여부, `tile_reason`은 준비 실패 사유입니다. 체크 여부만으로 활성화됐다고 판단하지 않습니다.

`LWIR650 E10` 또는 `temporal E13`을 선택하면 검출 모델 아래에 **박스 모양**이 열립니다. 기본은 상체입니다. 전신 추정은 현재 관절과 기하학적 비율로 표시 범위를 늘리는 기능이며, 전신 모델의 정확도를 뜻하지 않습니다. 추적·제어·채점용 원래 상자는 유지하고 사람 선택은 상체 위치를 누릅니다.

## 추종과 ID 인계

Python과 C++ v27을 함께 수정했습니다. 브리지의 `WEB_FOLLOW_CONTROL 1` 선언을 확인한 경우 새 인계 명령 `J old_id epoch new_id proof_frame`을 사용합니다. 제어 세대와 근거 프레임이 맞고 새 대상이 유일해야 승인합니다. Python은 일치하는 `R J OK`와 뒤이은 브리지 상태를 확인한 후 인계를 확정합니다. 정지 요청은 대기 중 선택·인계·Home·이동을 비우고 확인 응답을 받는 경로를 사용합니다.

외형과 위치를 확인하는 재포착 보호, 서로 유일한 최고 후보끼리 연결하는 KeepID, 확정 뒤 공개 ID 배정, 외형이 확인된 재포착의 기존 공개 ID 보존을 포함합니다. 기본 보호 로직 위에 얹힌 변경이며 실물 오추종 감소율을 이번 통합에서 측정한 것은 아닙니다.

**브라우저 종료 후 추종 유지**는 `LWIR_WEB_FOLLOW_PERSISTENT=1`로 명시적으로 켭니다. 기본은 기존의 브라우저 heartbeat 수명입니다. 켠 경우 웹 선택 명령 `W`를 사용합니다. 수동 이동, Home, 명시적 정지, 제어 오류와 관측·재획득 시간 제한은 여전히 별도로 처리합니다. TCP PC GUI의 `A` 선택은 세션 수명을 유지합니다.

변경한 `gimbal_bridge_v27`을 빌드하고 Python 서버와 함께 다음 정상 시작에 적용해야 합니다.

```bash
bash tracking_server/scripts/build_gimbal_v27.sh
```

운영 실행 설정이 별도의 브리지 실행 파일을 지정했다면 그 경로도 확인해야 합니다. 빌드만으로 실행 중인 서버가 바뀌지 않습니다. 자동 시작 Home은 추가하지 않았습니다.

## 녹화 확대 추종

녹화 화면에서 사람 상자를 누르면 가상 화면이 그 사람을 따라갑니다. 재생바의 **추적 확대**는 1~4배이며 기본 2배입니다. 빈 곳 클릭은 전체 화면, 되감기·다른 실행은 선택 초기화입니다. 겹친 상자나 다른 재생 실행의 클릭은 거절합니다. 모터에는 명령을 보내지 않습니다.

가려진 동안 `models/track/pos_gru_elapsed_10s.npz`를 읽을 수 있으면 이전 관측으로 최대 10초의 위치를 추정합니다. 파일이 없거나 이력이 부족하면 예측을 보장하지 않습니다. 가중치는 저장소에 추가하지 않습니다.

## 채점의 상체·전신 정의 확인

서버가 녹화를 준비할 때 모델과 정답의 박스 정의·검수 상태를 확인합니다. 확인되지 않으면 영상은 재생하지만 채점 수치는 내지 않습니다. 모델이 바뀌면 진행 중 점수를 무효화하고, 최종 결과 캐시는 모델·정답·검수·박스 정의가 다른 실행과 섞지 않습니다.

녹화 폴더에 `replay_box_contract.json`이 필요합니다. 필드는 `schema=reviewed-replay-boxes-v1`, `recording`, `human_reviewed=true`, `source_mot_sha256`, `source_review_sha256`, `source_box_definition`, `box_definition`입니다. 박스 정의는 `full_body` 또는 `head_to_hip`이며 검출 모델의 알려진 정의와 일치해야 합니다. 원본 MOT와 `review_state.json`의 실제 해시를 사용해야 합니다.

전신→상체 검수는 채점 대상 전체 사람에 대해 `boxes` 안에 `frame`, `id`, `reviewed=true`, `head_to_hip_xyxy`를 기록해야 합니다. 누락·중복·화면 밖·원본 사람 범위 밖 좌표는 거절합니다. 파일을 자동 생성해 검수 완료로 간주하지 않습니다.

제한된 기존 녹화에서 `box_mode=approx_upper_body`를 명시적으로 요청할 수 있으나, 결과에 근사 평가임을 표시합니다. 이 결과를 수동 검수 상체 정답의 성능으로 사용하면 안 됩니다. 일반적인 녹화·미확인 모델에서는 허용하지 않습니다.

## 진단 옵션

- `LWIR_IDENTITY_TRACE=1`: 최대 180프레임·프레임당 16행의 ID 진단을 메모리에 보관합니다. `GET /diagnostics/identity`는 localhost에서만 읽을 수 있습니다. 픽셀·파일 경로·외형 벡터를 기록하지 않습니다. 실제 직렬 쓰기 완료를 제공하지 않는 브리지에서는 전송 제안을 모터 실행 완료로 표시하지 않습니다.
- `LWIR_STAGE_TIMING=1`: 기존 단계별 시간 측정입니다. 추가한 `LWIR_STAGE_TIMING_AUTO=1`은 실제 GUI 실행기에서 자동 시작하도록 하는 선택이며 기본은 꺼짐입니다. `LWIR_STAGE_TIMING=0`은 자동 선택보다 우선합니다.
- NPU의 기존 `split_wait_mode` 파일 또는 `LWIR_SPLIT_PARALLEL_WAIT` 선택은 유지합니다. 백업의 `parallel`을 기본값으로 강제하지 않습니다.

## 적용과 검증의 범위

Python 단위·회귀 검사, 실제 C++ 실행기의 가짜 장치 검사, PC·휴대폰 Chromium 화면과 보드의 별도 임시 폴더에서 브리지 전체 빌드를 확인합니다. 실제 운영 프로세스의 교체·재시작, 분할 NPU의 실제 켜짐, 다인 추종과 성능 비교는 이 소스 통합과 별도입니다. 최신 검사 결과와 장치 미적용 상태는 `HANDOFF.md`를 확인하세요.
