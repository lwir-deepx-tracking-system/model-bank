검출 모델 설명
고르기
"검출 모델" 줄에서 누르면 재시작 없이 다음 프레임부터 그 모델로 검출합니다. 실패하면 이전 모델로 되돌립니다.
640x480 · 640x640
모델 입력 크기. 카메라 영상(640x512)에서 가운데 480줄을 씁니다. 640x480 모델은 그대로 넣고, 640x640 모델은 위아래에 회색 띠를 붙여 넣습니다(계산량이 더 큼).
(자동 등록)
코드에 미리 적어 둔 모델이 아니라, 서버가 models/detect/ 폴더에서 스스로 찾아 올린 파일. 파일 이름과 상관없이 parse_model 로 입력 크기와 출력 모양을 읽어 맞는 검출 모델만 올립니다. 10초 넘게 변하지 않은 파일만 받습니다(복사 중인 파일 제외). 이름은 같은 이름 json 의 display_name, 없으면 파일 이름 그대로입니다.
[NMS-free]
후처리 경로 표시. 표시 없는 모델은 출력이 6개(상자 3 + 분류 3)라서 오렌지파이 CPU 가 상자를 복원하고 NMS(겹친 상자 지우기)를 합니다. NMS-free 모델은 출력 1개 [1,300,6] (x1,y1,x2,y2,점수,종류)이 이미 완성된 목록이라 그대로 씁니다. 서버가 파일의 출력 모양을 보고 경로를 자동으로 고릅니다.
YOLOv8 · YOLOX
표시는 없지만 출력이 1개입니다 (YOLOv8 [1,20,8400], YOLOX [1,8400,21]). 상자는 파일 안에서 이미 풀려 나오고, 오렌지파이 CPU 는 다른 모델과 같은 규칙으로 NMS 만 합니다. 장치에서 정확도와 속도를 아직 재지 않았습니다.
주의
자동 등록 모델은 우리 카메라에서 오검출 검사를 거치지 않은 것일 수 있습니다. 기준 모델은 YOLO26m_(FLIR) 640x480 입니다.
위치 기억 · 신뢰도 설명 (Kalman filter · GRU · Mamba)
하는 일
사람을 놓친 동안(검출이 끊긴 프레임) 그 사람이 어디 있을지 추정합니다. 다시 검출되면 이 추정 위치와 겹치는 상자에 같은 번호를 잇습니다. 검출이 이어지는 동안의 상자와 Kalman filter 는 건드리지 않습니다.
Kalman filter (기본)
등속 모델 + 카메라 움직임 보정. 학습 모델 없음. 지금까지 쓰던 것과 완전히 같습니다.
GRU · Mamba
Kalman filter + 카메라 움직임 보정이 낸 예측 위치에 작은 보정값(중심 x,y · 폭 · 높이)을 더합니다. 보정값을 0 으로 두면 Kalman filter 와 같습니다. 자기 예측을 다음 프레임 입력으로 다시 넣는 방식(MambaTrack 논문의 autoregressive 규칙)으로 최대 60프레임까지 이어 갑니다.
입력 (프레임당 16개)
Kalman 속도 2 · 직전 검출과 예측의 차이 4 · 검출 있음 표시 1 · 카메라가 민 양 2 · 직전 두 프레임 사이 중심 이동 2 · 크기 변화 2 · log 높이 1 · 가로세로 비 1 · 놓친 프레임 수 1. 길이는 모두 예측 상자 높이로 나눈 값. 놓치기 전 최대 20프레임을 먼저 읽습니다.
출력
보정값 4개. 한 프레임에 중심은 상자 높이의 ±50%, 크기는 ±10% 를 넘지 못하게 막아 둠. 보정한 상자를 Kalman 상태의 위치·크기에 덮어씀(속도, 공분산은 그대로).
구조
GRU: GRU cell(은닉 40) → linear 4, 가중치 7,124개. Mamba: Mamba block 1개(d_model 32, expand 2, d_state 8, d_conv 4, Gu & Dao 2023) → linear 4, 가중치 9,124개. 둘 다 numpy 로 오렌지파이 CPU 에서 계산(NPU 안 씀).
쓰는 조건
놓치기 전에 5프레임 이상 연속으로 본 사람만. 그보다 짧으면 그 사람은 Kalman filter 만 씁니다. 계산 오류가 20번 넘으면 자동으로 Kalman filter 로 돌아갑니다.
학습
우리 카메라 야외 영상(seq_*)의 사람 궤적에서 검출을 일부러 끊고, 끊긴 동안의 실제 위치를 맞히도록 학습. 가중치 파일은 tracker/motion/pos_gru.npz, pos_mamba.npz. 새 파일을 넣으면 재시작 없이 목록에 뜹니다.
신뢰도
지금 가중치는 신뢰도를 내지 않습니다(시험용 1 epoch). 0~1 신뢰도를 같이 내도록 다시 학습하는 것을 준비 중입니다. 신뢰도가 낮으면 Kalman filter 값을 쓰고 예측 상자를 그리지 않게 됩니다.
지금 상태
서버 정보를 불러오는 중…
예측 상자 표시
"제어" 줄에서 켜면 짐벌이 따라가는 사람을 놓쳤을 때 그 사람의 추정 위치만, 같은 색 점선 상자와 "번호 predict" 로 화면에 그립니다(Kalman filter 일 때도 됨). 다른 사람의 추정 위치는 그리지 않습니다. 화면에만 그리고 짐벌에는 보내지 않습니다.
주의
추정 위치가 틀리면 다른 사람에게 번호가 넘어갈 수 있습니다. 검증된 가중치가 나오기 전에는 기본값(Kalman filter)을 쓰세요. 코드: pos_predict 함수, PosGRU · PosMamba 클래스.
Tracker 설명 (고른 것)
녹화 재생
초당 장 수
정답과 비교
재생을 시작하면, 검수한 정답 라벨이 있는 녹화는 여기에 1초마다 점수가 나옵니다.
숫자 설명
새 채점 · 옛 채점
같은 프레임을 두 규칙으로 셉니다. 새 채점은 무시 구역(라벨의 무시 상자, 가장자리에 걸친 좁은 사람)을 빼고, 옛 채점은 빼지 않습니다.
잘못 그린 상자
정답 사람과 짝이 없는 서버의 사람 상자 수. 있으면 안 되는 상자라 맨 위에 둡니다. 새 채점에서는 무시 구역 안에 반 넘게 든 상자는 세지 않습니다.
정답 사람
채점한 프레임들의 정답 사람 상자 수 (프레임마다 셈).
찾음
서버 상자와 짝이 된 정답 사람 수 (겹침 IoU 0.5 이상).
놓침
짝이 없는 정답 사람 수. "작은 사람"은 높이 32 px 미만 (놓쳐도 받아들일 수 있음), "그 밖"은 나머지.
찾은 비율
찾음 ÷ 정답 사람.
맞은 비율
찾음 ÷ (찾음 + 잘못 그린 상자).
번호 바뀜
정답 사람 하나에 붙은 서버 번호가 그 사람의 앞 번호와 달라진 횟수 (CLEAR MOT, Bernardin & Stiefelhagen 2008).
IDF1
사람마다 번호를 얼마나 끝까지 지켰는지. 채점한 모든 프레임에 걸쳐 정답 번호와 서버 번호를 하나씩 짝지어 셈 (Ristani 외 2016). 100 이 가장 좋음.
MOTA
1 − (놓침 + 잘못 그린 상자 + 번호 바뀜) ÷ 정답 사람 (CLEAR MOT). 100 이 가장 좋고, 0 보다 작을 수도 있음.
무시 구역 상자
새 채점에서 무시 구역 안이라 세지 않은 서버 상자 수.
완주 기준
녹화 한 편을 처음부터 끝까지 연속으로 한 번 재생한 결과를 기준으로 씁니다. 중간에 멈추거나 건너뛰면 완주 점수로 확정하지 않습니다. 다시 확인하려면 처음부터 새 재생을 시작합니다.
채점한 장
검수된 정답 라벨이 있고 서버 출력과 프레임 번호가 맞는 장면만 셉니다. 결과 아래에 전체 영상 진행량과 정답 비교 가능 장 수를 따로 보여 줍니다.
HOTA
사람 검출과 추적 ID 연결을 함께 평가하는 점수입니다. 한 번 완주한 뒤 계산 상태가 완료되면 표시합니다.
사람 mAP50:95 · AP50
저장된 사람 검출 후보를 정답 상자와 비교한 검출 점수입니다. 추적이 끝난 뒤 별도로 계산하며, 계산 중·계산 불가 상태를 구분해 표시합니다.
ID 변경
정답 사람과 연결된 추적 번호가 바뀐 장면을 영상 아래에 프레임 번호와 함께 표시합니다.
채점 규칙
사람만
정답 클래스 0 과 서버가 내보낸 사람 상자 (화면에 보이고 짐벌에 가는 상자, 640x480 좌표).
짝짓기
CLEAR MOT 방식 (Bernardin & Stiefelhagen 2008, py-motmetrics 와 같음): 겹침(IoU) 0.5 이상만, 하나는 하나와만. 앞 프레임에서 짝이었던 정답 사람과 서버 번호가 아직 IoU 0.5 이상이면 그대로 짝짓고, 나머지만 헝가리안 방법으로 짝짓습니다.
무시 구역
새 채점만: 라벨의 클래스 1 상자, 그리고 왼쪽·오른쪽 가장자리 4 px 안에 닿고 보이는 폭이 24 px 보다 좁은 사람. 짝이 없는 서버 상자가 무시 구역 하나 안에 반 이상 들어가면 잘못 그린 상자가 아님. 무시 구역은 놓침이 아님.
정답 라벨
tracks_edited_mot.txt (검수한 라벨)만 씁니다. 라벨에 있고 검수했다고 적힌 프레임만 채점. 자동 라벨(tracks_mot.txt)만 있는 녹화는 채점하지 않습니다.
프레임 짝
재생 카메라가 프레임마다 PNG 번호를 함께 보내고, 서버는 그 번호로 정답을 찾습니다.
그대로
재생 시작 직후 추적 기록이 없는 프레임도 넣어 셉니다. 숫자를 좋게 하려고 바꾼 것은 없습니다.
정답 상자
"정답 상자 그리기"는 이 화면 그림에만 그립니다 (흰 점선 = 사람, 분홍 점선 = 무시 구역). 짐벌에는 가지 않습니다.
결과 파일
재생을 멈추거나 바꾸면 서버 결과 폴더에 replay_eval_<이름>_<시각>.json 으로 남습니다. 파일에는 비교용으로 앞 프레임 짝을 보지 않고 프레임마다 헝가리안만으로 센 숫자(per_frame_hungarian)도 함께 적습니다.
녹화 재생 설명
하는 일
라벨 사이트의 녹화 폴더 하나를 카메라 대신 서버에 넣습니다. 검출·추적은 카메라 영상과 똑같이 돌고, 영상 맨 위 줄에 REPLAY 와 녹화 이름이 나옵니다.
짐벌
재생을 시작하면 짐벌을 멈추고, 재생 중에는 사람을 눌러도 손으로 움직여도 짐벌이 움직이지 않습니다. 재생을 멈춘 뒤에는 사람을 다시 누를 때까지 따라가지 않습니다.
카메라로
영상 아래의 카메라로 돌아가기 또는 Esc를 누르세요. 반복을 끄면 한 번 끝까지 재생한 뒤 마지막 장면에서 멈춥니다.
8비트 녹화
값이 0~255 를 늘린 것이라 온도 Filter(16비트 값)가 맞지 않아 사람이 걸러질 수 있습니다. 볼 때만 설정의 "온도 Filter"를 잠시 끄세요. 서버가 Filter 를 스스로 바꾸지는 않습니다.
측정
재생 중에도 측정할 수 있습니다. 측정 결과(summary.json, README_KO.txt)에 재생한 녹화 이름이 적힙니다.
길이
길이 제한이 없습니다. 장면은 필요할 때 하나씩 읽습니다.
영상 아래 막대
재생 중에는 영상 바로 아래에 재생 위치 막대, 재생·일시정지, −10초·+10초, 장 번호로 이동이 나옵니다. 막대는 놓을 때 건너뜁니다. 시간은 위의 "초당 장 수" 기준입니다. 장 번호는 1부터 셉니다 (1 = 녹화의 첫 장면).
건너뛰면
건너뛴 뒤 약 1.2초는 영상이 멈춘 듯 보이고, 그 사이 추적은 새로 시작합니다 (사람 번호가 새로 붙음). 짐벌은 건너뛰는 중에도 움직이지 않습니다. 먼 곳이나 뒤로 건너뛰면 PNG 녹화는 이 1.2초 안쪽, 측정 녹화(raw.gz)는 파일을 앞에서부터 다시 풀어야 해서 몇 초 더 걸릴 수 있습니다.
일시정지
멈춘 동안 같은 장면을 초당 5장 되풀이해 보냅니다 (서버가 카메라가 죽었다고 보지 않게, 화면이 살아 있게). 되풀이한 장면은 정답과 비교에 세지 않습니다.
점수 비교 재생

~
기본값 45000 ~ 0 (위쪽 제한 없음). 이 카메라 측정(11-10): 천장 조명 43,397 이하 · 방 안 사람 47,749 이상 · 가까운 사람 60,170 이상 → 그 사이인 45000. 주의: 화면 끝에 잘린 사람은 40,387까지 내려가 버려질 수 있고, 따뜻한 벽 물체(49,155 이하)는 이 값으로 못 거릅니다.
기본값 0.5. 측정으로 정한 값은 아닙니다(경험값, 검출 기본 점수 0.25의 두 배). 올리면 가장자리 오검출이 줄고, 화면에 들어오는 사람을 조금 늦게 잡습니다.
Filter 설명
Warmth range
상자 안의 따뜻한 부분(원시값 상위 5% 지점)이 최소 ~ 최대 안에 있을 때만 사람으로 인정합니다. 최소보다 차갑거나 최대보다 뜨거우면 버립니다. 카메라 16비트 원시값(0~65535) 기준. 최소 0 = 아래쪽 검사 끔, 최대 0 = 위쪽 제한 없음.
Edge confidence
화면 가장자리에 걸친 상자는 검출 점수가 이 값 이상일 때만 새 궤적으로 시작합니다. 이미 추적 중인 사람에게는 적용하지 않습니다. 0 이면 제한 없음.
온도 Filter 끄기
설정의 "검출 뒤 Filter" 줄에서 "온도 Filter"를 끄면 Warmth 검사만 꺼지고 숫자는 서버가 기억합니다. 다시 켜면 그 숫자로 돌아옵니다. Edge confidence 는 그대로 적용됩니다.
System
System 설명
카메라 초기화
카메라 프로그램(cam_pipe)을 정상 종료하고 다시 시작합니다. 영상이 안 들어오는 중이면 카메라 USB 초기화도 같이 합니다. 10~60초 걸립니다. USB 에 카메라가 아예 안 보이거나, 초기화하고 90초가 지나도 영상이 없어 다시 누르면 보드의 USB 전원(5V)을 3초 껐다 켭니다(케이블을 뽑았다 꽂는 것과 같음. 짐벌 USB 와 마우스도 같이 잠깐 끊김. USB 메모리·디스크가 꽂혀 있으면 전원을 끄지 않음).
서버 재시작
8090 추적 서버를 다시 시작합니다. 직전 실행 기록은 보관하고, 서버가 돌아오면 화면이 자동으로 연결됩니다.
검출 지연 줄이기 · NPU 0·1 번갈아 쓰기
영상 위에 있는 스위치입니다. 같은 검출 모델을 NPU 코어 0과 1에 올려 두고 영상을 한 장씩 번갈아 맡깁니다. 앞 장의 검출이 끝나기를 기다리지 않고 다음 장을 시작하므로 결과가 나오는 간격과 밀린 지연이 줄어듭니다. 한 장을 계산하는 시간이 줄지는 않고, 검출 결과는 같습니다. 처리 중인 프레임이 끝나면 서버를 다시 시작하지 않고 전환합니다.
오렌지파이 재부팅
짐벌을 멈추고 보드를 재부팅합니다. 1~2분 뒤 이 화면이 저절로 다시 뜹니다. 보드에서 돌던 다른 작업도 모두 끊깁니다. 부팅 후 5분 안에는 다시 눌러도 실행하지 않습니다.
