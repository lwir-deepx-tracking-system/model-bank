# YOLO26m 상체 박스와 전신 추정

2026-11-19 오렌지파이 8090의 상체 E10과 상체 박스 흔들림 E10+3 시험 모델을 기준으로 작성했습니다. 이 문서는 장치에서 확인한 구현과 측정 기록입니다. 8090에서 확인한 전신 투영과 E10+3 등록 상태를 설명하며, 이 커밋은 문서 업데이트입니다.

## 화면에서 고르는 방법

**검출 모델 → YOLO26 → 범용**에서 상체 E10 또는 상체 박스 흔들림 E10+3을 선택합니다. 선택한 모델 아래 **박스 모양**에서 범위를 바꿉니다.

| 옵션 | 화면에 표시하는 범위 | 좌표가 나오는 곳 |
| --- | --- | --- |
| 상체 · 머리~골반 | 머리 위부터 골반 근처까지 | YOLO26m-pose의 상체 박스 헤드와 현재 상체 표시 보정 설정 |
| 전신 추정 · 머리~발 | 머리부터 관측되거나 추정된 발 부근까지 | 같은 검출의 관절과 트랙의 상체 경계를 이용한 표시용 좌표 |
| FLIR · 640×480 | 검출 모델이 예측한 사람 전신 범위 | 박스와 점수를 출력하는 별도 FLIR 모델의 박스 헤드. |

E10과 E10+3에서 검출 모드는 별도로 고릅니다. **NPU 0·1 번갈아 쓰기**는 프레임을 두 코어에 한 장씩 맡깁니다. **한 장 분할 · NPU 0·1 동시 검출**은 같은 장을 좌우 타일로 처리합니다. 두 모드에서 상체와 전신 추정을 선택할 수 있습니다.

## 학습에서 박스의 경계를 정하는 과정

기존 관절 템플릿은 어깨 중심과 골반 중심을 잇는 길이를 1로 놓고 중간점을 원점으로 사용합니다. 얼굴의 가장 높은 점 위에 몸통 길이의 0.35, 골반 아래에 0.10을 여유로 둡니다. 가로 반폭은 어깨의 바깥 좌표에 0.25를 더해 정합니다. 일부 관절만 있는 영상에서는 유효 관절 두 개 이상으로 축척·회전·이동을 맞춥니다. 얼굴·어깨·골반의 가중치는 1, 팔꿈치·무릎은 0.30, 손목·발목은 0.15입니다. 이 템플릿은 학습용 상체 경계를 만드는 데 쓰입니다. [상체 템플릿 구현](../models/detect/build_scripts/yolo26m_pose_otp2_bodybox_build/skeleton_box.py)

11-19 상체 E10의 현장 라벨은 수동 MOT 박스로 사람을 확인하고 이전 E10의 상체 후보를 대응시켰습니다. 얼굴 점수 0.50 이상 두 점과 어깨 0.50 이상 한 점이 있어야 후보에 들어갑니다. 후보 면적의 75% 이상이 수동 박스에 포함되어야 하며, 위쪽 차이는 수동 박스 높이의 22%, 가로 중심 차이는 수동 박스 폭의 28% 이내입니다. 높이 비율은 0.35~1.10입니다. 매칭 1순위와 차순위의 점수 차가 0.075 미만이거나, 채택 상체끼리 IoU가 0.76 이상인 경우에는 해당 표본을 제외했습니다.

현장 439장과 기존 검수 211장, 총 650장을 사용했습니다. 새 현장 영상은 확인한 어깨·팔꿈치·손목·골반 좌표를 관절 감독에 사용했습니다. 가림을 표시한 관절은 좌표가 있는 경우에 가려진 좌표로 다뤘습니다. 미검수 관절과 미표기 인물의 배경 분류 손실은 마스킹했습니다. 추론 시 모델은 사람 박스, 검출 점수, COCO 순서의 관절 17개를 출력합니다.

E10+3은 이 상체 E10에서 650장으로 3에폭, 옵티마이저 126회 갱신한 시험 모델입니다. 두 프레임의 예측 중심 변화와 정답 중심 변화의 차이에 손실을 주고, 수동 박스가 있는 29쌍에는 폭과 높이 변화도 포함했습니다. 몸통 관절로 움직임을 확인한 101쌍은 중심 변화만 사용했습니다. 이미 학습에 사용한 쌍에서 손실의 효과를 측정했습니다. 별도 OTP2 934장에서는 상체 E10 대비 박스 mAP50–95가 **46.28% → 40.21%**, 관절 mAP50–95가 **78.35% → 74.58%**였으므로 E10+3의 정확도 우위는 확인되지 않았습니다. 전신 표시 수치는 별도 절을 참고하세요.

## 한 프레임을 검출하고 추적기에 넘기는 과정

1. 열화상 640×480에서 박스와 사람 점수, 관절을 풉니다. stride 8·16·32 격자에서 검출 박스에 해당하는 앵커의 관절을 꺼냅니다. 관절 격자 오프셋을 픽셀로 변환하고 가시성 점수에 sigmoid를 적용합니다.
2. 한 장 분할은 폭 384인 타일을 `x=0`과 `x=256`에서 잘라 128px 겹치게 만듭니다. 높이는 480px입니다. 오른쪽 타일의 박스와 관절 x 좌표에 256을 더한 뒤, 박스 중심이 `x<320`이면 왼쪽 타일을, `x≥320`이면 오른쪽 타일을 사용합니다. 양쪽 결과를 합쳐 사람 NMS를 적용합니다. 교대 모드에서는 각 프레임에 전체 640×480 입력을 한 번 넣습니다.
3. NMS 뒤, 이 프레임의 박스 배열과 사람 관절 배열이 정확히 일치할 때만 상체·전신처럼 겹친 중복 박스를 추가로 검사합니다. 통과한 사람 행과 관절을 함께 넘기고, 추적기는 기존 로직으로 현재 검출에 ID를 연결합니다. [검출 처리](../src/detect/detect_frame.py) · [분할 경로의 기반 코드](../src/detect/dual_tile.py)

### 중복 한 쌍을 판단하는 조건

- 작은 박스는 높이 48px 이상입니다. 얼굴 다섯 점 중 세 점과 어깨 두 점 중 한 점 이상이 각각 0.50 이상이어야 합니다.
- 큰 박스 높이는 작은 박스의 1.30~2.15배입니다. 머리·어깨 일곱 점 중 0.35 이상인 점이 최대 하나이고, 검출 점수는 작은 박스보다 높지 않아야 합니다.
- 작은 박스 면적의 74% 이상이 큰 박스에 포함되어야 합니다. 중심 x 차이는 작은 박스 폭의 16%, 윗변 차이는 작은 박스 높이의 15% 이내입니다.
- 큰 박스의 위쪽 45%에 신뢰할 수 있는 머리 중심이 정확히 하나 있고 그 머리가 위 조건에 해당할 때, 큰 박스와 연결된 관절 행을 함께 뺍니다. 머리가 두 개면 겹친 두 사람일 수 있어 보존합니다. 큰 박스 하나만 검출된 경우에도 해당 박스를 보존합니다.

임계값은 8090의 `src/detect/pose_duplicate.py` 구현 값입니다. 이전 녹화에서 나온 검출값으로 재현한 시험은 전체 입력과 분할 입력에서 각각 8개 중 중복 2개를 제거했고, 머리가 따로 확인된 사람은 남겼습니다. 최신 E10+3의 `seq_002` CPU 추론 표본 3장에서는 두 입력 방식 모두 장별로 5·5·4개가 나왔으며, 해당 표본에서 추가로 제거된 박스는 0개였습니다.

## 관절로 전신 경계를 추정하는 규칙

전신 추정은 모델이 검출한 상체 박스의 높이 `h = y2 − y1`와 현재 관절을 사용합니다. 현재 트랙 행의 검출 인덱스로 같은 프레임 사람 박스에 연결된 관절 한 묶음을 찾습니다. 연결된 관절이 없거나 동일 박스의 관절 대응이 여러 개일 때는 해당 트랙의 기존 박스를 표시합니다.

1. **관절 확인.** 골반·무릎·발목은 가시성 점수 0.55 이상이며 화면 안의 유한 좌표여야 합니다. 후보는 상체 박스 가로 경계에서 한 박스 폭 이내, 상체 윗변 기준 `−0.15h~+2.15h`에 있어야 합니다. 골반 y는 상체 윗변+`0.38h`에서 아랫변+`0.24h` 사이로 제한합니다. 골반→무릎과 무릎→발목 길이는 각각 `0.13h~0.74h` 안에서 인정합니다. 무릎이 골반보다 `0.08h` 이상 위에 있거나, 발목이 무릎보다 `0.10h` 이상 위에 있으면 해당 구간을 인정하지 않습니다. 좌우 다리는 각자 검사합니다.
2. **발목이 확인된 경우.** 가장 낮은 유효 무릎·발목 y에 `0.05h`를 더합니다. 기존 상체 아랫변보다 낮은 값으로 박스를 끝냅니다.
3. **무릎까지 확인된 경우.** 가장 낮은 유효 무릎 y에 `0.43h`를 더해 하체를 추정합니다.
4. **유효한 무릎과 발목이 없는 경우.** 유효한 골반의 평균 y를 상체 아랫변 ±`0.12h` 안으로 제한합니다. 골반이 없으면 상체 아랫변을 기준점으로 사용합니다. 그 아래로 `0.77h`를 더합니다. 선 사람의 전신 높이가 상체 높이의 1.77배라는 비율에 따른 추정입니다. 앉은 자세, 웅크린 자세, 하체 가림에서 실제 발 위치와 차이가 날 수 있습니다.
5. **옆 경계와 화면 경계.** 유효한 무릎·발목이 상체 좌우 밖에 있으면 `0.05h` 여유를 두고 바깥으로 확장합니다. 추적기의 상체 박스까지 포함시킨 뒤 네 모서리를 화면 안으로 제한합니다.

상체 높이가 100px이고 정상 골반이 상체 아랫변에 있을 때, 관측된 하체 관절이 없으면 화면 경계에 닿기 전까지 아래로 최대 약 77px를 연장합니다. 이 계산을 맡는 장치 함수는 `src/detect/pose_full_box.py`의 `project_box()`와 `project_tracks()`입니다.

### 화면에 그리는 좌표

- 배경 열화상은 그대로 표시합니다. 박스 좌표를 화면 배율로 변환할 때 상하 16px 패딩이 적용된 내부 좌표에서 y의 16px을 뺍니다. 웹 오버레이와 서버 JPEG에서 같은 표시 범위를 사용합니다. 박스 색과 숫자는 발행된 추적 ID에서 가져오고, 추종 중에는 선택한 사람의 박스가 강조됩니다.
- 전신 추정은 미리보기에서 트랙을 표시하는 단계에 적용합니다. 매칭, ID 계산, 정답 채점, 짐벌 조준 및 선택 위치는 기존 상체 추적 결과를 사용합니다. 사람을 선택할 때 상체 쪽을 누르면 됩니다. 별도 재생 비교 모드가 자체 채점 박스를 그리는 경우에는 그 전용 좌표로 표시합니다.
- `box_refine=body`는 상체 화면·짐벌용 박스의 크기와 비율을 보정하고 부드럽게 그리는 기존 기능입니다. 전신 선택 시 화면에 그리는 확장 경계는 위 관절 규칙으로 계산합니다. 흔들림 손실, 상체 화면 보정, 전신 추정은 각각 학습, 기존 표시·제어 보정, 표시 범위 계산에서 동작합니다. [박스 크기 보정](../src/track/box_refine.py) · [미리보기 경로](../src/web/page_handler.py)

## 검증 기록

- **전신 경계 표본.** 기존 E10의 `seq_003` 56장, 대응된 190박스에서 전신 정답과의 중앙 IoU는 0.427 → 0.744, 박스 밑변의 중앙 절대 오차는 60.4 → 4.8px였습니다. 해당 표본 190건은 모두 발목 경로를 썼으므로 무릎 추정과 가림 시 비율 추정의 정확도는 이 수치에 포함되지 않습니다.
- **E10+3 화면 확인.** 오렌지파이의 `seq_002`에서 상체와 전신 미리보기를 각각 출력했습니다. 두 장치 사진의 프레임은 228과 223으로 5장 차이가 있었습니다. 동일한 228번 프레임 비교는 E10+3 가중치의 CPU 추론과 실제 전신 투영 코드로 수행했습니다. 전체 입력·분할 입력 각각 5개 검출에서 같은 검출에 부여한 시험 ID와 행 수를 유지했고, 두 입력 모두 4개는 발목, 1개는 선 사람 기준 비율을 사용했습니다.
- **E10+3 실카메라 지연.** 카메라 약 30FPS, 각각 65초 동안 측정했습니다. 서버 수신→추적 완료 p95이며 브라우저와 물리 제어 응답은 포함되지 않습니다.

| 모드 | 추적 p95 | 최근 1분 추적 표본 | 측정 구간 입력 큐 버림 | 처리 순서 오류 |
| --- | ---: | ---: | ---: | ---: |
| NPU 0·1 교대 | 40.47ms | 1,800 | 0 | 0 |
| NPU 0·1 한 장 동시 분할 | 25.71ms | 1,799 | 1 | 0 |

분할은 이 구간의 지연 33ms 목표를 통과했습니다. 같은 모델을 선택한 `ptb_classroom2` 녹화 재생에서는 310개 추적 표본의 p95가 32.47ms였고 310장이 모두 발행됐습니다. 이 녹화에는 실카메라의 프레임별 코어 기록이 적용되지 않습니다. 프레임 누락 0장 조건까지 판정하려면 같은 구간에서 입력과 추적 처리 수, 큐 버림과 순서 오류를 함께 확인합니다. 녹화가 끝나면 최근 표본이 만료되므로, 오래된 재생 상태의 p95로 현재 카메라 지연을 판단할 수 없습니다. 비교할 때는 영상, 추적기, 화면 모드, 코어 모드와 관측 인원 수를 함께 기록합니다.
