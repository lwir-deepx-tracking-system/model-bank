# 실시간 JPEG 작업 분리: PC 비교 결과

실시간 카메라의 화면 그리기·JPEG 압축을 추적 처리에서 분리했습니다. `LWIR_ASYNC_PREVIEW=1`일 때만 켜지며 기본은 꺼짐입니다. 녹화 재생은 동기 방식으로 유지합니다. 모델, 해상도, JPEG 품질, 검출·추적·평가 입력과 제어 계산은 바꾸지 않았습니다.

## 무엇을 확인했나

- 저장 RAW16 영상 218장과 고정된 기존 박스·ID 1,860행을 PC에서 사용했습니다. 이 행들의 정답 여부는 확인하지 않았으므로 정확도 측정이 아닙니다.
- 원래 HEAD, 새 기본 경로, 새 옵션 경로에서 218장 전체의 JPEG 바이트·제어 입력·평가 입력 해시가 일치했습니다. GT/예측 표시, 모의 C++ 추적 결과 표시, 녹화 표시 분기는 각각 10장씩 추가 대조했습니다.
- 67개 회귀 검사가 통과했습니다. 대기 이미지 상한, 압축 실패, 원본 변조 방지, 소스 전환, 녹화 첫 프레임, 종료 중 스냅숏 차단, 클릭 ID 불일치 차단을 포함합니다. 독립 검토에서 발견한 전환 문제를 수정했습니다.
- 추적과 채점은 218장 모두 처리합니다. 압축이 밀릴 때 건너뛰는 것은 미리보기 표시 대기뿐입니다. 처리 중 한 장과 최신 대기 한 장을 유지합니다.

## PC 시간 비교

각 표는 동기→분리→분리→동기 순서의 두 회차 범위입니다. 매 장에 같은 24ms 모의 선행 작업을 넣었습니다. Windows 대기 시간과 CPU 상태가 포함되므로 NPU 시간·실카메라 fps로 해석하지 않습니다.

## 판단과 적용 범위

혼잡 때 JPEG 압축 때문에 다음 추적 입력까지 기다리던 문제는 PC에서 줄었습니다. 그러나 혼잡 조건의 JPEG 준비 지연은 오히려 늘었습니다. 이를 화면 지연 개선이나 전체 33ms 달성으로 보고하지 않습니다. 별도 스레드도 같은 CPU를 쓰므로 Orange Pi에서는 자원 경합을 다시 측정해야 합니다.

`/perf`는 추적 결과 처리 시점, `/healthz`는 JPEG 준비 시점의 지연입니다. 브라우저 전송·표시, 카메라 노출, 실제 모터 응답은 측정하지 않았습니다. 웹 클릭 보호는 서버가 마지막으로 게시한 그림을 기준으로 하며, 느린 브라우저가 실제 보고 있는 프레임 식별까지 구현한 것은 아닙니다.

이 보고서의 PC 검증 시점에는 장치 접속·서버 재시작·M1 실행·Git push를 하지 않았습니다. 이후 사용자 승인으로 `da5d3c5`를 main과 장치에 반영하고 두 지연 옵션을 켰습니다. 장치 회귀 67개·검증 코드 11개의 해시·실제 프로세스 환경값·prefetch 로그·8090 옵션을 확인했습니다. 카메라는 USB 목록에 없고 입력 0장이므로 실제 영상 지연은 미검증입니다. 최신 적용 결과는 [HANDOFF](../HANDOFF.md)를 확인합니다. 코드 기본은 꺼짐이고 예측 제어 실기 튜닝은 보류합니다. 카메라 복구 뒤에는 동일 조건에서 추적 출력 간격과 실제 화면 지연을 함께 비교해야 합니다.

장치에서 두 옵션을 함께 쓰려면 `scripts/live.env`에 아래 두 줄을 추가하고, 기존 부모 실행기를 정상 종료한 뒤 표준 실행 스크립트로 다시 시작합니다. 기존 모델·제어 설정은 유지합니다.

```sh
export LWIR_LIVE_READY_PREFETCH=1
export LWIR_ASYNC_PREVIEW=1
```

압축 작업 분리만 되돌릴 때는 두 번째 값을 `0`으로 바꾸고 부모 실행기를 재시작합니다. `/healthz`의 `async_preview=true`는 옵션 생성 확인이며 실제 영상 출력이나 성능 확인은 아닙니다.

검사 명령(PC, 장치 사용 없음):

```sh
python -B -m unittest tracking_server.src.web.test_preview_pipeline tracking_server.src.gimbal.test_live_tracks tracking_server.src.gimbal.test_observation_transport tracking_server.src.camera.test_replay_end tracking_server.src.camera.test_replay_eval_prefix tracking_server.src.track.test_replay_metrics
python -B tracking_server/page/build_page.py --check
node --check tracking_server/page/js/15_perf_graph.js
```

이전 v2·v3 비교와 실패 기록은 보존했습니다. 최종 v4 원자료에는 입력·코드·결과 해시와 회차별 시간이 포함되며, 원본 영상·개인 경로는 공개 문서에 넣지 않았습니다.
